# Tinytune UI Design：安静的唱片索引

> 2026-11-19 · 双端 P0 界面交付稿 · [PRD](prd.md) 定义行为，[Roadmap](roadmap.md) 定义交付顺序。本文是文本设计规格，不是已渲染或已验证的高保真稿。

## 1. 设计 Brief

**目标用户和任务**：本地有一批已经整理好的音频文件。用户应该凭目录或熟悉的歌手快速听到音乐，并在任何页面知道正在播什么。音乐来自既有文件夹，界面既不能让人误以为「已复制」，也不能把授权失败说成「歌曲被删」。

**设计取舍**：以大封面为中心的「唱片墙」适合少量整齐专辑，缺封面时会失去辨识度；纯文件管理器虽然密度高，却让用户再次面对目录层级。选 **「安静的唱片索引」**：以歌手和可扫读的文本为主，浏览中小面积使用封面，把大封面留给专辑详情和正在播放。默认使用系统原生控件；采用[「松笺」视觉主题与「琴身嵌梅」图标](brand/README.md)：浅色用暖纸白与松墨绿，深色用墨绿底与浅苔绿。淡金五瓣梅仅嵌在图标的琵琶琴身上；警告色继续单独承担状态含义。不自绘系统导航或权限弹窗。

**三条检验规则**：

1. **首屏做一件事**：空库只有一个主要入口「添加文件夹」，不先问权限，不用轮播介绍。
2. **导航不打断音乐**：换页、输入搜索、扫描和调整排序都不接管队列；发声或换歌必须来自明确的播放动作（自动推进遵循播放模式）。
3. **失败能继续**：能修复的问题就地给动作；不靠颜色、图标或自动消失的提示承载重要信息。

## 2. 信息架构和平台布局

**返回行为**：从歌手／专辑详情返回保存列表位置；从播放页打开队列后，先关闭队列才退出播放页；关闭播放器只还原原页面，不暂停。Mac 搜索和播放详情不额外开主窗口。不会并排弹出扫描、授权和队列多个模态层。

Mac 侧栏在载入或曲库读取失败时显示对应提示，不误报为空；空库显示「尚未导入歌曲」，未添加来源显示「尚未添加文件夹」。来源不可用时显示数量，不以颜色作为唯一提示。

曲库没有歌曲时：保留唱片插画和一个主要入口。没有来源时说明原文件留在原处，提供「添加文件夹」；已有来源时说明目录仍然保留，提供「查看来源」。

### 内容圆角与歌曲状态

- 曲库和搜索的歌曲、歌手以组为单位使用 16 pt 连续圆角底板，使用内缩细分隔线；不为每首歌另铺白卡。专辑网格的封面与标题共用一张卡，详情摘要与来源目录沿用同一底板。原生设置表单和队列保留系统分组样式。
- Mac 单击选歌：行内 10 pt 连续圆角淡苔绿／深松绿底，不加前导竖线或外框；键盘焦点用不同底色区分。Return／双击播放，空格仍控制当前播放。iPhone 点按即播，不引入桌面式持续选中底。播放状态与时长并排，不增加歌名／副标题之外的独立一行；空间不足时状态仅显示图标并保留无障碍标签。播放状态与选中或焦点无关；长标题允许换行，辅助字号可将时长和状态一同移入副行。


## 3. 核心旅程

| 旅程 | 用户看到的顺序 | 成功判定 |
| --- | --- | --- |
| 首次出声 | S-01 空库 → 系统选目录 → S-05 扫描及确认摘要 → 回音乐库 → S-02 点播 → S-06 | 用户知道原文件仍在原处；确认后不自动播放；可定位实际出声的控制与曲目 |
| 找一首记得名字的歌 | S-04 输入「晴天」→ 曲目分组 → 点播某个版本 → S-07 查看待播 | 不同版本可凭封面、歌手／专辑及版本后缀区分；搜索默认不修改队列 |
| 续播和切歌 | 冷打开 → S-06 已暂停位置 → 明确点播放 → 设备媒体控制 | 重启没有声音；锁屏与应用看到同一首歌和进度 |
| 找回不可用歌曲 | S-02／S-06 点「查看来源」→ S-08 重新授权／重连后重扫 → 回原页面 → 用户再播 | 原索引和可匹配 ID 保留；能区别「未连接」「需授权」「文件缺失」；不自动播放 |

## 4. 逐屏规格

| ID／画面 | 信息顺序与关键交互 | 状态与细节 |
| --- | --- | --- |
| **S-01 音乐库／空库** | 标题「音乐库」→ 唱片插画 →「添加你的音乐文件夹」→ 主按钮「添加文件夹」。不附加浏览方式、目录结构或原文件处理说明。 | 首次无队列时不画空播放器。已建库但所有来源不可用时保留列表，显示一条可操作的状态横幅以及「查看来源」；不回退成首次使用画面。 |
| **S-02 歌手与歌曲列表** | 歌手行：40 pt 方形封面／占位、歌手名、「3 张专辑 · 24 首」、详情指示。歌曲行：封面或曲号、歌名、实际歌手／专辑、时长与更多菜单；歌曲页标题旁有排序操作。歌手详情先显示歌手名和「播放全部」，再按专辑分组展开曲目。 | iPhone 点行播放曲目（歌手行进入详情）；Mac 单击选中曲目，双击或 Return 点播，可通过行菜单点「播放」。正在播用状态标识与无障碍文案，暂停时标记「已暂停」，不假装仍播放。不可用项仍可检查：显示原因，点播改为恢复提示。 |
| **S-03 专辑浏览与详情** | 封面优先，小屏双列或自适应，卡片下方显示专辑名和归属歌手；辅助字号切单列。Mac 网格卡宽从约 148 pt 起。详情先封面与专辑资料，再「播放全部」，再按碟和曲号展示；单碟省略碟标题。 | 手机详情在宽度允许时用 112 pt 封面与文字并排，窄屏或辅助字号改上下排版。Mac 详情封面约 160 pt。不在封面上叠文字。无可播放曲目时禁用「播放全部」并显示原因。 |
| **S-04 搜索** | 未输入时一行提示「按歌曲、歌手或专辑搜索」，无历史推荐。结果顺序「歌曲 → 歌手 → 专辑」，各分组标题展示数量；点击歌手／专辑进详情、点击歌曲在歌曲搜索结果快照里播放。 | 搜索读取已有库，不在等待时清空整页；过滤输入使用约 150 ms 去抖，旧查询结果不得盖过新查询。无结果写「没有找到“{query}”」，保留查询，提供「清除搜索」。空库提示先添加文件夹。 |
| **S-05 导入／重扫** | 使用系统文件夹选择器，保留简短的选目录提示，不重复说明原文件处理方式。独立扫描面板先显示「正在检查音乐文件」和不定进度指示，附已检查／可导入计数与「取消」；首次导入以「3 首可导入 · 1 项跳过」呈现摘要，未跳过时只显示可导入数量，主按钮使用主题强调色，文案为「导入 3 首」；重扫与重连保留影响数字的对比。跳过原因可展开查看样本文件名。 | sheet 在小屏切到全高度以容纳摘要；只有新增、更新或确认缺失等可提交的变化时给提交按钮；没有变化用「完成」。首扫没有可用音乐显示「选择其他文件夹」；部分失败仍可提交有效部分，明确「部分文件未检查，已有记录保留」。确认提交后短暂禁止重复点击与关闭，失败恢复可操作状态并保留原库。取消或关闭未提交摘要不改库。 |
| **S-06 迷你播放器／正在播放** | iPhone 迷你条：约 36 pt 封面、两行歌名／歌手、播放／暂停与下一首；封面和曲名为独立的展开区，控制按钮不触发展开。全屏页从上到下：关闭、封面、曲名和歌手、进度／时间、上一首／播放／下一首、播放模式／队列。Mac 底栏左曲目信息、中段传输和进度、右侧播放模式／扬声器／队列，各有独立按钮。点扬声器在上方打开圆角音量气泡，原生竖直滑杆向上增大音量并实时显示百分比；点外部或按 `Esc` 关闭。窄窗让进度换到第二行，不藏主要控制。Mac 展开态主栏陈列大封面、文字和错误详情，避免与底栏重复放两套传输控件。 | 封面在 iPhone 参考 `min(可用宽度 − 48 pt, 320 pt)`，文字较大或横屏时缩封面、控件保持目标尺寸；内容可以滚动。拖动显示预览时间，松手提交；语音操作可直接调整位置。加载不清空曲名；出错显示「无法播放这首歌」和「重试／下一首」，有来源故障时另给「查看来源」。iPhone 音量只使用系统。 |
| **S-07 队列** | 固定「正在播放」区和按实际顺序的「接下来」区。行显示曲名、歌手，点待播行开始播；通过行菜单「从队列移除」，iPhone 另支持滑动。iPhone 保留原生 sheet；Mac 使用锚定队列按钮的原生弹层，顶栏显示「队列」和待播数。短队列随内容收高，较长时仅「接下来」区域滚动。 | 正在播放行无移除操作，P0 不显示拖动手柄；跳到后面用被选曲目明确反馈已换歌。待播区空时写「没有待播歌曲」，不误称播放已结束；若还有待播但当前项被移除，展示「当前没有播放曲目」，仍可手动选播。 |
| **S-08 来源／关于** | iPhone 以三项底栏中的「来源」承载目录管理：空态使用藏谱匣风格的文件夹图标、原文件留在原处的说明和「添加文件夹」主按钮；有来源时先显示目录总数，再显示目录名、曲数、最后扫描时间和异常状态。卡片动作分为「重新扫描／重新授权」与「更多操作」，图标 13 pt、无底板、保留相邻的 44 × 44 pt 点击区；移除来源执行前单独确认。来源页右上角提供独立的「关于曲笺」入口，展示本地播放器与不上传音乐库的说明；不再把内容单薄的设置页作为底栏 Tab。Mac 悬停短暂停留后显示自定义文字气泡；移开即收起，不抢焦点或拦截点击，两端控件均保留无障碍标签。迁移确认显示匹配和未匹配数。 | 同名来源附可区分的本机位置提示，不在默认列表暴露完整路径。移除确认只显示具体对象，Mac 默认聚焦「取消」。移动目录、外接卷离线和授权失效的操作不同，不提供含混的「修复」按钮。

**播放按钮细节**：播放模式按钮每点一次切换「顺序播放 → 单曲循环 → 随机播放 → 顺序播放」。只显示当前模式的图标（编号列表、带 1 的循环箭头、交叉箭头）；辅助功能读取「播放模式」与当前模式，图标颜色不是唯一反馈。Mac 音量使用实心扬声器，以声波和静音斜杠区分状态。无 seek 能力时显示 `—:—` 表示未知时长（已知时照常显示），并禁用滑块；超过一小时显示 `h:mm:ss`。迷你条仅在有当前或待播时出现；仅有待播时显示「待播放」并可开始首个可播项。

## 5. 状态、文案和恢复动作

文案以说明发生了什么、用户能做什么为准，不呈现原始系统错误或绝对路径。示例中的 `{n}` 为本地化插值；英文复数使用 String Catalog 规则。

| 状态 | 反馈文案示例 | 就地动作 |
| --- | --- | --- |
| 用户取消系统选取 | 无报错，返回原页 | 可再次「添加文件夹」 |
| 扫描进行中 | 「已检查 {n} 个文件」；不定进度，无假百分比 | 取消 |
| 未发现支持的音乐 | 「这个文件夹没有可加入的音乐。请选择包含音频文件的文件夹。」已知跳过原因另列 | 选择其他文件夹 |
| 已确认是未下载的文件 | 「有 {n} 个文件还不在此设备上。」 | 查看详情；提示用户先在系统文件管理器中将文件保存到本机 |
| 来源需授权 | 「Tinytune 无法继续读取这个文件夹。请重新选择原文件夹。」 | 重新授权 |
| 来源离线 | 「来源未连接。重新接入原磁盘后可以再扫描。」 | 重试／重新连接 |
| 暂时无法读取 | 「部分文件暂时无法读取，已有记录已保留。」 | 重新扫描 |
| 曲目确认缺失 | 「在原文件夹里找不到这首歌。音乐库记录仍保留。」 | 查看来源；重扫或清理 |
| 提交失败 | 「没有保存这次更改。原有音乐库未受影响。」 | 重试／关闭 |
| 移除单曲或来源 | Mac 右键、iPhone 长按使用原生短菜单，移除项单列在底部。确认气泡 Mac 280 pt、iPhone 288 pt；只显示标题和对象名（最多两行）。 | 取消／确认；确认使用松笺主题色，Mac 默认聚焦取消；大字号下按钮可换行。 |
| 恢复快照但当前项不可播 | 「上次播放的歌曲暂不可用。」保留曲名和位置，保持静音 | 查看来源／下一首 |
| 队列不可推进 | 「队列里没有可播放的歌曲。」 | 查看队列／回音乐库 |
| 无法打开音乐库 | 「暂时无法打开音乐库。现有数据已保留。」 | 重试；不提供自动重置 |

## 6. 视觉系统与组件

### 6.1 语义色

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `surface.canvas` | `#FAF8EF` | `#20261F` | 主内容背景 |
| `surface.raised` | `#FFFEF8` | `#293228` | 非系统样式的播放器／局部摘要承载面 |
| `content.primary` | `#242B23` | `#EEF1E6` | 标题／主要文本 |
| `content.secondary` | `#586154` | `#B8C2B1` | 元数据、时间和辅助信息 |
| `accent.brand` | `#355541` | `#C4D5A7` | 主按钮填充、播放进度及自定义选中标记 |
| `accent.onBrand` | `#FAF7EA` | `#263529` | 主按钮标签 |
| `accent.subtle` | `#E6EADA` | `#354332` | 自定义选中背景，配 `accent.brand` 文本／图标 |
| `sidebar.selection` | `#47604C → #355541` | `#4B6249 → #354B39` | Mac 侧栏当前页底色，用松绿渐变衬托白色文字与图标 |
| `tab.selection` | `#355541` | `#C4D5A7` | iPhone 系统底栏选中图标和文字，不改变系统选中底形 |
| `status.problem` | `#9B3C49` | `#FFB3BC` | 警告文字和图标，不满屏铺红 |

使用系统 `separator`、菜单、焦点和选中语义处理原生控件；品牌色不覆盖系统高对比度状态。自定义文本与底色先按常规字号 ≥4.5:1 设计；有意义的非文本控件边界与相邻底色目标 ≥3:1。表中主按钮文字实色组合浅／深分别约 **7.74:1／8.27:1**；实际渲染仍需检查透明度、高对比模式、禁用状态与焦点环。封面取色不用于标题、警告或传输按钮底色。

### 6.2 尺度、字型、组件

- **字型**：系统字体语义级别 `.largeTitle`（顶层标题）、`.title2`（详情）、`.body`（行主标题）、`.subheadline`（副标题）、`.caption`（非关键元数据）；时长用等宽数字。Mac 采用本端语义大小，不把手机大标题生搬过来。
- **间距**：4／8／12／16／24／32 pt；iPhone 内容边距 16 pt、Mac 主栏 24 pt；行高参考手机 56 pt、Mac 44 pt，内容可扩高。按钮点击区不随可见图标缩小，iPhone 至少 44 × 44 pt。封面圆角行内 6 pt、卡片 8 pt、大图 12 pt；系统弹层不用自定义圆角。
- **封面**：方形整幅取景（普通专辑封面可 `aspectFit`，避免剪去封面文字），真实封面保留原貌；无封面或加载失败时，双端共享的封面组件显示[「折页唱片」](../packages/TinytuneKit/Sources/DesignSystem/Resources/Artwork.xcassets/FoldedRecord.imageset/FoldedRecord-Light.svg)。占位图保留原矢量轮廓，改用松笺主题的低饱和松绿，可随系统浅色／深色切换，从 34–40 pt 的行内缩略图到 320 pt 的播放页大图使用同一矢量轮廓。专辑名保留在封面外；真实封面读取不变。
- **原创插画**：空库保留小幅「星轨唱片」，内容区右下另铺[「山间听曲」](brand/README.md#原创山水背景山间听曲)：macOS 横卷铺开，iOS 窄屏将低矮山脊、飞鸟与小亭放在操作区下方。列表与播放器文字后保持纯底；插画不响应触控、不参与 VoiceOver，且不做持续动效。
- **语言**：开发版应用内使用简体中文，不受宿主语言影响；系统界面仍跟随系统设置，原始音乐标签与文件名不翻译。
- **共享组件**：`tuneCard()`、`ArtworkTile`、`TrackRowContent`、`TransportControls`、`PlaybackScrubber`、`LibraryStatusView`、`SourceStatusBadge`、`ImportSummaryContent`。组件通过状态值与 action 注入；导航容器、权限选取器、破坏性对话框归平台 app，不在 `DesignSystem` 里访问数据库。
- **动效**：播放页使用系统转场；信息更新不做视觉跳动。开启「减弱动态效果」时不缩放封面、不做持续波形或位移动效；扫描进度仍有计数和文字。

## 7. 无障碍与 Mac 键盘

- **VoiceOver**：曲目行朗读「标题，歌手，专辑，时长，状态」；更多菜单与播放主动作可分别访问。播放器控制朗读「暂停／播放」「播放模式，随机播放」「播放模式，单曲循环」等。封面旁已有等价文本时隐藏装饰图。Slider 具有时间值和可调语义；默认增减 5 秒并限制在有效时长内。不每秒播报进度；只公告导入结束、失败与用户发起的明显状态变更。
- **阅读和可点性**：iPhone 覆盖 Dynamic Type 至最高辅助字号；行允许多行、控件可垂直重排，详情保留完整标题，时长列可移到副行。Mac 表格在窄窗口优先折叠次要元数据；支持 VoiceOver、系统显示缩放和清晰焦点。长文件名、繁简混合及中英混排不能挤掉主操作。
- **焦点**：进入播放页先聚焦页面标题／关闭入口，关闭后回迷你条原控件；导入摘要就绪时公告摘要，关闭后回添加按钮或原来源行。队列移除后焦点转到下一行或队列标题。自定义视觉状态不替代原生键盘焦点。
- **Mac 命令**：`⌘O` 添加文件夹，`⌘F` 全库搜索，主列表 Return 播放已选曲目，空格播放／暂停，`Esc` 关闭最上层弹层或退出搜索焦点，`⌘,` 打开设置。空格／Return 不覆盖文本输入、滑块、其他原生控件和系统对话框。菜单项与工具栏共用可用状态和动作，不提供绕过确认的删除快捷键。

## 8. 原型与交付切片

- **先验原型**：进入 M1 时先以 SwiftUI Preview 的样本状态做 S-01、S-02、S-05、S-06；优先审查「空库到出声」及「离线到恢复」两条旅程。用合成或经授权封面／元数据，不用用户私有音乐库截图作为交付物。
- **M2**：补音乐库详情、搜索、重连与错误文案，以同一份样本目录验证双端一致。**M3**：补全正在播放、队列与系统状态，不把静态封面或无响应控件当成完成。P1 控件未实现前不展示。
- **预览样本**：空库；30 首混合目录；无封面；长的中／英／多字符标题；同名歌不同版本；无搜索结果；有未下载及跳过项；授权失效；来源离线；扫描部分失败；提交失败；已暂停队列；不可 seek；待播为空；大字号。

## 9. 设计验收

1. **截图核查**：两端分别截空库、歌手／歌曲列表、导入成功／部分失败、播放、队列、重连。覆盖 iPhone 窄屏／参考尺寸、Mac 最小／参考窗口，以及浅色／深色、超大字号和高对比。检查末行不被播放器挡住、标题不遮盖按钮、队列不挤出主控件。
2. **可用性任务**：按 PRD AC-01 从零导入并播放；再让参与者找到不同版本、从失败状态恢复、说出「移除」是否会删除文件。记录用时、误操作和参与者用语；按问题频次改文案或信息顺序，再用同一任务验证。
3. **可访问性与交互**：iPhone VoiceOver 走完添加、播放、seek、移除待播与恢复；Mac 只用键盘走完搜索、点播、打开／关闭队列及安全退出删除；检查焦点、触控区域、朗读与 Reduce Motion。
4. **规则一致性**：断网、后台、切歌、重启和来源失联时，列表、迷你条、正在播放及系统媒体面板不会互相矛盾；扫描或更换视图不打断声音。对照 [PRD](prd.md) R-01～R-07 和 AC-01～AC-07 登记差异再放行。
