## 方案说明

1. 沿用 Web 顶部卡片的纸色、青绿山水和暖日；风景靠上靠右，210–300 pt 渐隐，内容区留白，不纵向拉伸山形。
2. 音乐库新增按钮去掉可见外框；来源页的关于与新增图标置于标题上方，**关于左、新增右**。视觉图标 24 pt，点击区域至少 44 × 44 pt。
3. 来源页合并重复摘要，名称、曲数、状态、扫描入口依次呈现；保留来源更多操作与重新授权流程。
4. 关于弹窗示意高 366 pt，建议按内容自适应；导入确认态示意高 546 pt。主按钮固定底部，长内容与大字号应支持扩大弹窗及独立滚动。上述数字仅为本稿默认排版，不是最终固定高度。
5. 新增文件夹仍调用 iOS 系统文件夹选择器；交互稿直接展示选定文件夹之后的导入确认，不替换原生 Files 界面。
6. About 的标题、文案与品牌区为建议稿。正式实现需保留原有国际化、VoiceOver、Dynamic Type、导入差异与取消能力。

## 边界

- 所有歌曲、文件夹名称、曲数均为**布局示意数据**，不是实时读取。
- 不访问真实音乐文件，不播放音频，不导入、删除或扫描文件。
- 设计稿阶段未修改 SwiftUI、Web 业务逻辑或 App 资源，验证与构建不代表原生验收。
- 复用的唱片图和 App 图标来自本项目；原生落地继续使用 SF Symbols，HTML 中的小型几何控制图标仅为审阅占位符号。
- 交互稿为 HTML 设计审阅载体，不代表计划将 App 改为 WebView。
- 设计稿确认前不进行生产实现，不创建提交或推送。

## 2026-11-24 追加修复：当前实现

- 本目录 HTML 和既有截图保留为原始确认稿，不冒充最新原生截图。上述顶部渐隐、左对齐标题、已连接状态和行内扫描为首轮方案，以下实现取代这些部分。
- 当前音乐库、搜索、来源使用一幅通屏日／夜山水；源稿在 `docs/brand/landscape/Page-{Light,Dark}.svg`，并非只补一段顶部插画。标题居中；来源卡片去掉文件夹图标、已连接状态和行内重扫，维护动作保留于更多菜单，移除页尾原文件／上传说明。

- iOS 曲库切换歌手／专辑／歌曲重建对应滚动容器，避免跨分组复用旧偏移。曲库与搜索仅折叠明确的同录音音质副本，不改来源文件、旧队列或歌词 ID。
