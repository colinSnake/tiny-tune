# Tinytune Roadmap：从首次出声到双端发布

> 2026-11-19 · 规划稿。范围以 [PRD](prd.md) 为准，交互以 [UI Design](ui-design.md) 为准。本文是里程碑路线图，不是已完成清单或逐文件实现计划。

## 交付策略

优先验证两个无法靠模拟器证明的问题：**原目录授权冷启动后是否仍有效**，以及 **iPhone 后台与 Mac 系统媒体键能否控制同一个播放器**。首条原生 UI 与功能链路可与真机验证并行开发；队列、错误恢复和体验随后补齐。不先做 P1，开发版不等于通过真机栅栏。

**本地试用与正式发布分开推进。** 已实现但受设备或环境限制的非必要项，保留实际通过／失败／阻塞／未测证据，不反复追测、不阻塞本地试用；遇到具体问题再重开排查。详见[本地试用交接](local-preview.md)。这不是正式发布门槛的豁免。

| 里程碑 | 累计成果 | 依赖 | 单人有效工作量估计 |
| --- | --- | --- | --- |
| M0 可行性 | 两端本地目录授权、音频与系统控制验证 | 无 | 2–4 天 |
| M1 原生工程与纵向切片 | 选小目录、保存索引、点播一首 | 开发可并行；退出依赖 M0 | 3–5 天 |
| M2 音乐库闭环 | 整理、查找、重扫、恢复授权和安全移除 | M1 | 5–8 天 |
| M3 播放闭环 | 队列、续播、系统控制及双端播放器 | M1；与 M2 集成 | 5–8 天 |
| M4 v1.0 验收与分发 | 可安装的双端签名产物与验收记录 | M2、M3 | 4–7 天 |
| M5 v1.1 候选 | 按使用反馈选取 P1，不影响 v1.0 | M4 | 另估 |

总估算约 **19–32 个有效工作日**（单人串行，不含设备准备、签名账号、用户测试招募及商店审核等待）。M0 后按实测重估；任何双端 P0 门槛未通过，不把日期当成放行依据。

## M0 · 可行性栅栏

**状态：进行中，未放行。** [M0 真机记录](m0-device-validation.md#开发版验收进展)汇总当前开发版进展并保留 macOS 陈旧书签异常的历史探针证据；当前结果以[开发版真机记录](native-development-validation.md#iphone-格式矩阵与来源恢复)及[后续进度／单曲循环复验](native-development-validation.md#iphone-进度与单曲循环复验)为准。下方完整门槛不勾选。

**验证范围**：R-01、R-02、R-07；为 AC-02、AC-05、AC-06 固定验收条件。

- [ ] 选定并记录 Xcode／Swift／macOS runner 版本、最低系统测试环境和各一台基准 iPhone／Mac（机型、系统、可用存储、构建配置）；确认 iPhone 签名团队与 Mac 分发方式。
- [ ] 用最小试验工程验证两端「系统选择 → 书签 → 冷启动恢复 → 打开目录内音频」。在沙盒 Mac 测本机与外接卷；在 iPhone 测「我的 iPhone」、源被移动／撤权与回到前台。记录不可用 File Provider 的行为，不用模拟器推断真机结果。iPhone 同提供者移址后回前台、冷启续播通过；Mac [本机目录更名、重新授权、冷启续播](native-development-validation.md#mac-格式矩阵与本地来源重连)通过。iPhone [合成来源容器消失、显式重连及冷启续播](native-development-validation.md#iphone-格式矩阵与来源恢复)通过；实际撤权、Mac 物理外接卷仍阻塞，第三方 File Provider 掉线未测。
- [ ] 用合法 fixture 建立双端 × codec／容器矩阵：MP3、M4A AAC、M4A ALAC、裸 AAC、WAV、FLAC；分别记标签读取、出声、seek、切曲和损坏／受保护内容的拒绝行为。Mac QA [六种合成样本](native-development-validation.md#mac-格式矩阵与本地来源重连)经应用导入、起播、seek、暂停与队列自然切歌通过，坏 MP3 拒绝；iPhone [同批六种样本](native-development-validation.md#iphone-格式矩阵与来源恢复)通过导入、时钟推进及自然切曲，拒绝坏 MP3，ALAC seek 通过。[iPhone 补测](native-development-validation.md#iphone-进度与单曲循环复验)确认 MP3、M4A AAC、裸 AAC 与 FLAC 的暂停端点 seek；新增四种的精确曲中 seek 未测，WAV 独立 seek 阻塞，扬声器听感和受保护样本未测。
- [ ] 真机试验 iOS 锁屏／后台切曲和媒体命令；Mac 试验系统 Now Playing、媒体键与应用内空格，验证命令只注册一份。iPhone 锁屏为用户手测通过；后台／控制中心和 Mac 空格及焦点隔离为工具实测通过。Mac 进程内媒体状态已核对；实体「下一首」[首次用户手测未通过](native-development-validation.md#mac-实体下一首首次手测)；[单 QA 隔离复测](native-development-validation.md#mac-隔离媒体会话与格式预检)也失败。系统服务收到播放状态变更，但真实按键后未观察到命令进入 App；系统面板显示为用户手测；系统播放与单次「下一首」已由工具确认，切歌只推进一首并保持暂停。[后续只读诊断](native-development-validation.md#mac-实体键只读诊断)确认键盘有消费控制描述符，但尚无实际按键输入证据；仍未定位首个丢失边界，未修复。面板暂停按钮、动态进度及硬件键重复分派仍待验。
- [ ] 固定 fixture 和期望 JSON：30 首首次使用包、1,000 首扫描包、5,000 首大库、双端文件故障样本及扫描权限情景；记录构造脚本、体积、曲长分布、测量起止点和样本来源。

**退出条件**：两端本机目录可跨冷启动打开；MP3 与 M4A（AAC）能播放、seek；后台和系统命令核心路径在设备上成立。其余格式标注实测支持／不支持，不以扩展名承诺。支持组合的交集是共同发布列表。若任何本地 P0 失败，先记录证据并评估替代 API 或范围；不悄悄改成复制式导入、不因 M1 开发已经开始而略过 M0 放行。

## M1 · 原生工程与纵向切片

**状态：开发中，未退出。** 两端已能构建，Mac 小样本核心链路已走通，iPhone 模拟器已验证启动、空库和小样本文件夹导入。详见[原生开发版验证记录](native-development-validation.md)。

**验证范围**：R-01、R-02、R-06 的最小链路；UI S-01、S-05、S-06 的最小版本。

- [x] 建根 workspace、两个原生 app targets 和共享 schemes；接入 `TinytuneKit` 的 `Domain`、`Library`、`Playback`、`DesignSystem`。部署目标锁定 iOS 17／macOS 14；平台配置和签名能力分别管理。
- [x] 定义首版 SwiftData schema、来源与曲目稳定键、隔离写入器；实现最小目录授权适配、扫描预检及确认写入。
- [ ] 双端各实现空库、选择目录、最小摘要和曲目列表；接同一播放服务，实现点播和暂停，再做重启后的目录与曲目复读。实现已接线；Mac 与 iPhone 独立 QA 小样本已在真机跑通目录导入、点播和冷启动复读；[Mac Release 试用包](local-preview.md#本轮验证)已通过 30 首导入、坏文件跳过、点播与冷启原位续播，原文件一致；iPhone 同批样本扫描预览通过，确认入库、点播和冷启未测。完整退出条件仍待验。
- [ ] 建立 `scripts/` 统一入口和 macOS CI：逻辑测试、两个 scheme 的构建与测试、fixture 生成检查；CI 不存个人设备授权、书签或生产签名密钥。统一脚本与工作流已添加，本地构建和包测试通过；远端 CI 与基准 fixture 检查待执行。

**退出条件**：干净检出能复现双端构建；双端导入 30 首本地样本并播出，重启后不重选目录可再播；音乐文件没有被复制到容器或改写。CI 能从提交状态复现此最小链路的自动化部分。

## M2 · 音乐库闭环

**验证范围**：R-01～R-05；UI S-01～S-05、S-08；AC-02、AC-03。

- [ ] 补齐解析、专辑歌手聚合、曲序、封面占位及磁盘缓存；用输入目录树＋期望 JSON 验证 tag 与路径冲突、混合目录、多碟及同名曲目。
- [ ] 实现可取消的扫描、分原因摘要、原子确认、增量重扫、明确缺失与暂不可用的区分；测试重复选择、部分失败、确认前目录被移动、提交出错和冷启动清理。
- [ ] 双端完成歌手／专辑／歌曲三种浏览、详情、排序与全库搜索；展示不可用状态和重连入口。搜索与大库列表按基准样本测试。[Mac 真实曲库抽验](native-development-validation.md#mac-真实曲库抽验)已确认 59 首入库，以及歌名／歌手／专辑搜索和空结果；[Mac 合成数据性能基线](native-development-validation.md#mac-合成数据性能基线)已有 1,000 首扫描器与 5,000 首存储／搜索核心逻辑数据；[搜索缓存复验](native-development-validation.md#搜索缓存落地复验)已确认 Mac 加入来源后自动刷新同一查询，大库端到端和 iPhone 基准未测。
- [ ] 实现「来源」中的重扫、恢复授权、来源迁移、恢复已移除曲目及清理缺失；完成单曲／专辑／歌手／来源移除；确认不触及原文件并向播放服务发送受影响曲目 ID。已补齐显式迁移的相对路径预览与保留索引的重连，[iPhone 容器重建用例](native-development-validation.md#iphone-格式矩阵与来源恢复)通过，完整 M2 验收未完成。

**退出条件**：AC-02、AC-03 在两端通过；重扫、取消或失败不会破坏旧库；所有破坏性文案明确操作对象是索引。M2 可独立演示完整的“查找并播放”路径。

## M3 · 播放闭环

**验证范围**：R-05～R-07；UI S-06、S-07；AC-04、AC-05。

- [x] 用固定随机种子测试底层队列的随机、跳播历史、跨轮上一首／下一首与队列移除。跨轮覆盖保留为底层回归，不再提供列表循环模式。
- [x] 补齐故障候选有界跳过、无可播项停止与重试、迟到事件隔离；已通过自动回归和 [Mac 合成曲库复验](native-development-validation.md#不可播放曲目恢复复验)。
- [x] 实现按序队列的本地续播和移除联动；通过快照／seek 测试及 Mac 合成曲库冷启动复验，详见[验证记录](native-development-validation.md#本地续播复验)。 [Mac 真实曲库抽验](native-development-validation.md#mac-真实曲库抽验)另外确认 MP3／FLAC 抽样播放和 MP3 冷启动保留曲目、进度及待播顺序。
- [x] 接入 Mac 底栏与 iPhone 全屏页的单一模式按钮（顺序／单曲循环／随机），持久化实际历史与随机待播顺序；兼容旧续播记录。见 [Mac 控件复验](native-development-validation.md#播放模式控件复验)和 [iPhone 真机模式切换](native-development-validation.md#iphone-格式矩阵与来源恢复)；[MP3 真机跨曲末重播](native-development-validation.md#iphone-进度与单曲循环复验)已验证同曲、原待播不变。
- [x] 在 iPhone 真机验收冷启动续播、回主屏后的自然切歌与检查点推进，以及控制中心的播放、暂停和切歌。见[实体 iPhone 复验](native-development-validation.md#实体-iphone-复验)。
- [x] 完成 iPhone 物理锁屏场景验收（用户真机手测确认；与控制中心测试分开记载）。见[实体 iPhone 复验](native-development-validation.md#实体-iphone-复验)。
- [ ] 接入 iPhone 迷你条／全屏播放／队列，Mac 底栏／展开播放页／音量／队列；暂停、加载、结束、错误及不可用控制都有对应反馈。
- [ ] 双端接入系统媒体状态；真机回归锁屏、后台、线控、音频打断及外接卷掉线。验证媒体键、按钮和菜单命令不会产生不同队列状态。iPhone 系统「文件」合成预览抢占后暂停、原位手动续播通过（工具实测），真实来电未测、耳机／线控阻塞。Mac 底栏命令与队列通过对照；实体「下一首」两次用户手测未通过（隔离复测无 App 回调，[后续只读诊断仍未定位根因](native-development-validation.md#mac-实体键只读诊断)），系统面板播放与单次切歌通过（用户操作、工具回读），面板暂停与动态进度待测，外接卷仍阻塞。详见[真机追加验证](native-development-validation.md#2026-11-20-真机追加验证)。

**退出条件**：AC-04 和 AC-05 通过；从 UI、锁屏、耳机或媒体键控制都遵守同一播放规则；浏览和扫描不会打断当前播放。

## M4 · v1.0 发布栅栏

**状态：本地试用包已就绪，正式发布未放行。** 2026-11-20 [本地试用交接](local-preview.md)：Mac 包解压启动并完成 30 首用例；iPhone 开发签名包已在登记真机安装和启动。非必要受阻场景延后，不把本地试用写成 M0／M3 或正式发布通过。

- [ ] 跑完 AC-01～AC-07，记录环境、版本、结果与复现步骤；确认最低系统和一个较新系统的实际覆盖情况。未达到性能目标时先定位，不以未测或模拟器成绩冒充真机通过。
- [ ] 按 [UI QA](ui-design.md#9-设计验收) 覆盖两端、浅／深色、长标题、超大字号、VoiceOver 和 Mac 全键盘路径；完成简中／英语文案核对与无障碍验证。
- [ ] 用已签名的上一版测试构建和发布候选版验证安装、冷启动、断网、迁移、失败恢复、重连及卸载烟测；验证原目录不受移除与卸载影响。
- [ ] 打包两端自用可安装版本，记录安装与签名步骤、确切音频支持矩阵、依赖和隐私说明；发布前核实实际分发渠道所需的签名／公证、隐私披露与清单适用性。公开商店发布不是这次里程碑的前提。

**放行条件**：两端均有可安装签名产物；全部 P0 验收通过；零已知数据损坏／误删、启动崩溃或核心播放阻塞。候选版不合格则停发；已有用户数据不能靠回装旧二进制和破坏性重建解决，迁移缺陷优先前向修复并保留旧库。

## M5 · P1 选择顺序

1. **整理可纠正**：先确认实际误归类样本，再做解析来源切换和本地覆盖项。验收：预览可取消、应用后不丢曲目 ID、不改音频标签。
2. **Mac 导入更顺手**：拖入文件夹调用与系统选择器相同的授权与摘要链路。拿不到持久授权时回退到系统选取，不把一次性访问当作已成功导入。
3. **队列更好编辑**：重排和「下一首播放」。先定义与随机、循环和历史的交互；验收包含 VoiceOver 和键盘可用的替代操作。

播放列表、跨来源内容去重及菜单栏播放器先保留在 P2；不因准备数据模型而提前承诺界面或交付日期。
