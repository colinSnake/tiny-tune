# 随机播放与实际播放历史实施计划

> 在当前原生 monorepo 实施；先观察测试失败再实现。未经要求不暂存或提交，不使用真实音乐库。

**目标**：独立开关随机播放，上一首按实际经过的曲目返回；冷启动保留随机模式、实际历史与待播序列，保持暂停。

**依据**：[PRD R-06／R-07、AC-04](../../prd.md)。本轮不改变失败耗尽策略，也不替代 iPhone 真机验收。

- [x] `Domain/PlaybackQueue.swift` 分开保存源顺序、实际历史、向前重播路径与本轮待播。`setShuffle(_:using:)` 和 `advance(mode:automatic:using:)` 可注入 RNG；随机轮不重复，列表循环开启时跨轮避开刚结束的曲目，单曲循环不消耗待播。跳播只记录离开的当前项；上一首把离开的曲目放到向前重播路径首位且不消耗本轮待播；移除清理相关历史和未来项。
- [x] `Playback/PlaybackSnapshot.swift` 写入版本 2 的完整队列。版本 1 读取现有当前项、位置、循环和按序尾部；因旧记录没有实际历史，不凭空生成。无效记录继续降级为空播放器。`Player` 对账时保持随机序列，只剔除无效 ID；播放器和预览队列使用同一状态。
- [x] `apps/Shared/PlayerViews.swift` 为 macOS 底栏、iOS 全屏播放页增加独立随机按钮：开关状态、中文可访问性标签、可见状态和 macOS 悬停提示；保持既有窄窗口布局和四 Tab。
- [x] 固定种子执行队列测试、快照迁移与冷启动测试；执行 `scripts/check.sh`，用 Mac 独立测试版的合成曲库验证随机与循环独立、跳播历史、重开保持随机及待播顺序。更新路线图与原生验收，明确 iPhone 真机边界。

## 实际结果

- 原实现无法编译新增接口测试；完整实现后新增回归成功复现「从新轮次往前退再返回会跳过一首」，独立维护重播路径后通过，含该状态的 JSON 往返。
- `scripts/check.sh`：31 个测试通过、3 个目标构建通过；Mac 复验旧快照、A 跳 C、上一首回 A／下一首回 C、随机与循环独立、退进程后状态和待播顺序不变。详见[验证记录](../../native-development-validation.md#随机播放与实际历史复验)。
- iPhone 本轮仅构建；未执行真机冷启动、后台和锁屏验证。
