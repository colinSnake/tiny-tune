# Workbench Reading Layout Implementation Plan

**Goal:** 落地用户确认的歌单／播放器／歌词版式，使用现有本地软糖体，并保留可信时码的实时跟随。

**Design:** 已确认「听页 Web 工作台设计稿」，用户补充正文不过大、页面标题和歌词用软糖体。

- [x] 为版本标题、纯文本分段、独立播放卡与字体写回归测试，先确认测试失败。
- [x] 实现 `app/workbench-reading.ts` 中仅供显示的标题／署名处理，并更新 Workbench、歌曲行和播放器；不改变搜索、下载或歌词原文。
- [x] 调整 `app/workbench.css` 为四周 12px、桌面优先保证 640×360；歌词正文 16px，宽屏与视频并排，空间不足放下方。
- [x] 验证本地同版 LRC 高亮、拖动、点击跳转与暂停跟随；外站嵌入或纯文本不假装同步。完成全部 Web 测试、类型检查、干净构建和 Chrome 预览。

**验收（2026-11-25）**

- Chrome：使用合成的 42 秒音频与配套时码，验证连续播放逐句高亮、拖动进度条、点歌词跳到 27 秒、手动浏览暂停自动滚动和返回当前句；候选时长不符时仅阅读，浏览器实际时长不符时不高亮或跳转。
- Chrome：使用实际《告白气球》B 站录音棚试听版检查 1440、1280、1024、390、320px，均无横向溢出。宽屏视频 640×360，窄屏等比缩放；歌词独立滚动，页面标题与 16px 歌词均加载本地软糖体。B 站词曲署名单独显示，外站视频不联动该纯文本。
- Web 测试 `node --import tsx --test test/*.test.ts`：133 通过；`tsc --noEmit`、清理目标后的 Vite 前端与 esbuild 服务端构建通过。字体由服务运行时提供，Chrome 已验证加载。
