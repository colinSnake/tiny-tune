# 本地续播实施计划

> **For agentic workers:** 逐项实现和执行红／绿测试；未经用户要求不提交。此轮在当前工作区执行，不改动旧音乐库格式。

**目标：** 冷启动恢复上次的曲目、队列、播放模式和进度，保持静音，用户明确播放后再打开文件并 seek。

**架构：** `Playback` 模块原子写入版本化的本地 JSON，只保存曲目 ID 和播放状态；`AppState` 在曲库索引读取后注入播放器。AVPlayer 仍通过现有授权 resolver 打开文件。快照不参与 SwiftData 迁移，也不包含书签、URL 或音频数据。

**规格：** [PRD R-07／AC-04](../../prd.md)。原生 Swift 6，macOS 14／iOS 17；不使用真实曲库验收。

- [x] 先测试快照重读、静音恢复、旧 ID 对账、损坏／过新快照和新播放器续播 seek；观察原实现缺失。
- [x] 在 `PlaybackSnapshot.swift` 实现版本校验及原子读写；在 `Player.swift` 维护检查点、恢复暂停状态、处理异步 seek。播放时每 5 秒节流，暂停、切曲、队列变更及离开前台时另行保存。
- [x] `AppState` 在载入曲库后恢复；`TinytuneApp` 在离开前台、Mac 正常退出前写检查点；Mac 单独测试恢复时不申请音频能力、不自动换歌。
- [x] 跑 `scripts/check.sh`，用合成曲库复验重开、恢复时静音、手动继续和跨冷启动待播顺序，记录尚未验证的实机边界。

## 实际结果（2026-11-19）

- 红测：变更前续播测试无法编译，缺少 `PlaybackSnapshotStore`；不是运行期失败。
- 绿测：`scripts/check.sh` 通过，10 个续播、5 个曲库、4 个领域测试全部通过；macOS、iOS 通用设备（无签名）、iOS 模拟器目标均构建成功。
- Mac 独立测试版通过播放中 `⌘Q` 后的冷启动续播：保留当前歌曲、约 8 秒的进度、列表循环和编辑后的待播，保持暂停；点播放后从原位置继续。详见[原生验证记录](../../native-development-validation.md#本地续播复验)。
- Mac 缺歌复验：暂时移走当前合成音频，重开即显示「无法播放」和查看来源入口，保留原进度；点击重试失败后出现「从头播放」。放回文件并点击该按钮，仍播放原曲，从 0 秒重新开始。
- 未做实体 iPhone、锁屏／后台播放、系统媒体键、低版本系统及外接卷掉线验收。随机播放和实际播放历史留待下一轮。
