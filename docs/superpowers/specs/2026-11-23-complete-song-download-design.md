# Web 整曲与歌词下载设计

## 目标与范围

把 Web 工作台的默认入口从「查元数据后自己补音源」改成「搜到录音后直接下载整曲和同版本歌词」。用户不需要导入音频、提供直链或手动找歌词。音频来源可扩展，不绑定某个站点，但只有能拿到明确允许下载的整曲文件且已找到同一录音的歌词时，才显示「下载整曲＋歌词」为可用。旧的本地补词操作保留在次级入口；CLI、原生播放器、Vite + React、Fastify、pnpm 及现有端口均不变。

## 来源选择

- **推荐：官方可下载曲库优先。** 首个适配器使用 Jamendo 官方 API。它以曲目 ID 标识录音，可搜索歌名和歌手，返回是否允许下载、文件入口和部分曲目的歌词。使用服务端 `JAMENDO_CLIENT_ID`，不借用别人的凭据。上线前检查 API 使用条款及录音和歌词许可。它是独立音乐曲库，不承诺覆盖特定商业歌手。
- **可扩展：创作者提供下载的 B 站或第三方作品。** 将其作为另一个录音来源，仅接入能确认整段音轨、作品版本及下载许可的作品或由发布者提供的下载入口。保留来源和版本标注。视频字幕与歌词分开处理；纯对白、剪辑、翻唱、混剪和带片头的版本不能冒充原唱录音，不自动沿用原唱的时码。首版不依赖该来源，也不把仅能在线播放的地址当作可下载地址。
- **不推荐：搜到同名就抓第一个音轨。** spotDL 的音源和歌词分别接入、LRCGET 的同名歌词文件值得借鉴。它们不证明跨站同名结果就是同一录音，也不代替来源的下载许可。

参考：Jamendo API 的 `tracks`、`tracks/file` 文档；GitHub `spotDL/spotify-downloader`、`tranxuanthang/lrcget`、`yt-dlp/yt-dlp` 的 Bilibili 提取器。

## 用户流程

1. 首页搜索歌名或歌手，保留 Enter 搜索。结果卡片显示标题、歌手、专辑或版本、时长、来源以及下载状态。
2. 选中具体录音版本后，在详情里试听并看歌词。播放器和下载都绑定同一个来源曲目 ID；没有可验证的整曲资源时，试听仍可用，但不能点整曲下载。
3. 默认动作「下载整曲＋歌词」返回一个 ZIP：包含完整音频、同主文件名的 `.lrc` 和简短的来源/署名清单。音频不重编码。若只有对版纯文本，改标「下载整曲＋纯文本歌词」；歌词文件可以沿用 Tinytune 识别的同名 `.lrc`，但内容不生成时码，清单记录 `plain`。本期不做单音频文件内嵌标签或多选批量下载。
4. 搜不到、仅试听、没有歌词、版本待核对、来源限流或尚未配置时，明确说明缺什么，不弹出浏览器业务确认框，也不要求导入音频才能继续搜索。

## 服务端与歌词决策

- 来源适配器按 `provider + sourceTrackId` 标识录音。搜索返回元数据和下载状态，不将第三方直链当作客户端上传参数回传给服务器。详情请求才读取完整歌词，下载时再次按 ID 核对下载许可和音源；只访问经过配置验证的来源及其文件重定向，不做任意 URL 代理。
- 优先使用来源附在同一曲目 ID 上、有明确使用条件的歌词。补词使用现有匹配逻辑并收紧自动确认：歌名、署名、时长及已知版本须一致；缺少证明、候选冲突或时码落在音频外则不自动下包。已有的纯文本与时码解析可复用，不把帖文、弹幕和字幕默认当作唱词。
- 下载按请求限流，设并发、超时和文件大小上限。支持取消；先读完并验证完整音频与可用歌词，再发送 ZIP，断流、权限变化、长度异常、歌词丢失均返回具体错误，不产生看起来成功的残包或歌词空包。保留现有歌手搜索的限流提示与退避机制。

## 验收

- 用已授权测试录音检查：从搜索到试听和完成下载不经过本地导入；解压得到可播放到结尾的实际音频及同名歌词；有时码时 Tinytune 随播放定位，纯文本没有伪造时码。
- 测试同名不同版、仅试听、禁止下载、歌词缺失或冲突、失效/中断音源、取消及 429/503。固定测试夹具覆盖业务分支；真实平台验收另外使用有效的开发者 Client ID 和一首音频与歌词均允许使用的作品。未取得真实录音验收时，不把合成样例当作平台接入成功。

## 实施中确认的来源边界

Jamendo API 条款限制以离线访问为目的的应用。其曲目级下载标记不能替代产品级授权，也不能替代歌词使用许可。默认提供已核实的独立作者授权录音作为无需账号的入口；Jamendo 配置后可搜索和试听，只有取得相应许可并配置明确批准的曲目 ID 后开放打包。内置曲目以原版音频与歌词内容摘要锁定版本，原始素材不进入仓库。
