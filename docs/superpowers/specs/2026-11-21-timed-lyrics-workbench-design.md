# 时码歌词与独立采集工作台

日期：2026-11-21

## 范围

Tinytune 在 iOS 和 macOS 播放本地音频时展示歌词；独立 Web 页面和命令行脚本按歌手查找曲目、匹配歌词并导出。不在 App 内放采集入口，不让 App 联网找词。两个部分用同目录、同文件主名的 `.lrc` 衔接：例如把 `晴天.lrc` 放在 `晴天.flac` 旁。

工作台收集曲目**元数据**和可用歌词，不下载、托管或代理音频。用于操作者有权获取和保存的歌词；公开 API 可访问不代表歌词可以公开再分发。首版不做公开歌词库、逐字高亮、译文对照、时码编辑、音频标签写入或跨端同步。数据源的收录范围不代表歌手全集。

## 原生播放

### 界面与行为

- iOS 在「正在播放」页提供歌词切换按钮；切换后歌词替代封面区域，保留播放和进度控制。macOS 在播放控制区提供歌词按钮，在曲库右侧开关歌词栏，不改现有队列入口。
- 跟随模式下用字号、字重和颜色标出当前句，只在当前句变化时滚动。播放和暂停都按 `Player.position` 定位；拖进度条确认后、点歌词跳转、切歌、循环回到开头和本地续播都以播放器的实际位置为准。第一句时间之前不高亮。
- 用户手动滚动时暂停自动跟随，但当前句继续更新；点「回到当前句」恢复。切歌恢复跟随并清掉旧歌词。点击有时码的歌词调用现有 `Player.seek`，不改变暂停或播放状态；不可定位时不触发跳转。
- 加载中、纯文本、未找到和无法读取分别呈现；纯文本可以滚动但不显示跳转和跟随。缺词、坏文件、加载超时或授权失败不得阻塞或暂停音频。歌词行支持键盘或辅助技术触发，不逐句强制抢焦点或播报，减少动态效果时不强制动画。

### 读取与时间轴

- 只在歌词界面可见时异步读取当前曲目的 sidecar，以曲目与来源为加载标识，并丢弃快速切歌后返回的旧结果。不改曲库表、不扩大授权，也不把歌词加入音频索引。关闭重开歌词区可重新读取，无须重扫音乐库。
- 根据 `Track.path` 只替换末级文件扩展名为 `.lrc`，保留目录、主名大小写和标点。在 `Library` 内复用 `FolderAccess` 的书签、安全作用域和路径校验；仅打开授权根目录内的本地普通文件，不跟随链接或别名，不主动下载云端占位。读取设 1 MiB 上限。
- 首版支持 UTF-8（含 BOM）、LF／CRLF、`[mm:ss]`、`[mm:ss.x]`、`[mm:ss.xx]`、`[mm:ss.xxx]` 和同行多时间标签。元数据标签不显示；`[offset:N]` 表示正值提前、负值推迟，以毫秒处理并将负结果归零。时码排序，重复时间的非空行一起展示；仅有空内容的时码可清除当前高亮。没有有效歌词时码但有正文则作为纯文本；空文件为无歌词，无法解码为无法读取。
- 使用排序后的整数毫秒时间轴，取不晚于当前进度的最后一组行。Swift 与 Web 用同一份合成测试样例校验时码解析、偏移方向和边界。

## 工作台与脚本

### 结构

独立项目位于仓库的 `tools/LyricsWorkbench/`，前端使用 Vite、React 和 TypeScript，API 使用 Node.js 与 Fastify，依赖统一由 pnpm 管理。开发时 Fastify 在同一端口承载 API、Vite 中间件与热更新 WebSocket；生产时由 Fastify 提供 Vite 构建后的静态资源与 API。命令行复用同一套 provider、匹配规则和导出模块，不依赖启动网页。首版本地运行，仅监听回环地址，无数据库、账户或遥测。本地音频及其路径不上传，服务端不持久化歌词；导出文件由用户主动保存。

使用公开 API 编写采集脚本，不依赖播放器网页或私有接口：

| 数据 | 来源与边界 |
| --- | --- |
| 歌手候选、曲目 | MusicBrainz：搜歌手后以 MBID 分页浏览录音，展示曲名、歌手署名、可用专辑信息、时长。按 recording MBID 去重，不把同名不同录音合并。 |
| 歌词候选 | LRCLIB v1 搜索：按曲名和歌手查询，使用返回的时码或纯文本。首版只搜已收录内容，不触发补采、不用 beta 和写入接口。 |

请求由服务端或命令行发往两个固定 HTTPS 来源，不接受任意抓取地址。配置并附带包含项目名、版本和联系地址的 `User-Agent`。MusicBrainz 串行，每次请求开始至少间隔 1 秒；LRCLIB 串行，每次请求结束至少等待 1 秒。对 429／503 尊重 `Retry-After`，带少量随机抖动；超过客户端可等待时间时显示可重试状态，不提前继续发请求。网络超时、非预期响应和限流不报成「未找到」。取消时停止安排新请求，保留已有结果；只重试失败项。歌词只在当前工作会话内复用，不长期缓存。

### 操作流程

1. 输入歌手，手动提交搜索。从候选中选择目标歌手，显示可用的别名、地区、消歧说明，避免把同名歌手合并。曲目列表每页最多 50 条，可继续加载；空结果和请求失败提供不同的后续操作。
2. 用户勾选当前已加载的曲目，启动批量匹配。按曲显示「等待」「匹配中」「有时码」「仅纯文本」「待确认」「纯音乐」「未找到」或「请求失败」；显示已处理数、总数、停止和重试入口。界面窄时改为上下排列，不挤压歌词预览。
3. 点某一曲查看歌词和时码。可选浏览器支持的本地音频试听（用本地对象 URL，切换和离开时释放）；提供逐行高亮、点行跳转。没有音频时仍能预览时码和文字。选择本地音频后单曲导出建议使用其主名，不把文件名或音频发到服务端。
4. 单曲导出 `.lrc`；批量导出 ZIP，包含已确认的 `.lrc` 和 `manifest.json`，记录曲目 ID、匹配状态、时长、歌词来源 ID 和输出文件名。纯文本可导出同扩展名以便 App 降级展示，绝不伪造时间。可仅导出曲目 manifest。不把未确认、不存在歌词的曲目写成歌词文件。

### 匹配、命名与 CLI

- 只有曲名与署名规范化后匹配、录音和歌词都具有时长且相差不超过 2 秒时，才允许自动匹配。规范化仅处理大小写、全半角和空白，不丢弃 `Live`、`Remix` 等版本信息。已知专辑一致时优先；双方专辑明确但无交集，或最高可信度候选有不同歌词时，标「待确认」。缺时长或署名不同但存在相关候选时，也由用户查看后选择，不默认为列表首项。
- 导出使用经过净化的单个文件名，不使用曲目数据组目录。默认按曲名命名；同名或大小写冲突时附上可区分的 ID 后缀，并在 manifest 中标明。CLI 不覆盖输出目录中已有的 `.lrc`，碰撞时保留旧文件并在 manifest 中注明。用户把歌词放入授权音乐目录之前，须按实际音频文件主名对齐，尤其是有曲序前缀、同名版本或碰撞的文件。
- CLI 输入歌手名称、输出目录；只有唯一精确候选时自动选定，遇到同名或仅模糊候选时输出候选和 MBID，要求以 `--artist-id` 重跑。默认最多处理 50 条录音，`--limit` 可指定 1–500 条并自动分页。命令行只导出自动确认的匹配和 manifest，数据源出错保留部分结果并报告失败。Web 提供候选人工确认。

## 验收

| 层级 | 首版验收 |
| --- | --- |
| Swift 单元测试 | 同名路径生成、安全目录与读取边界、LRC 解析、偏移、多标签、纯文本及当前句边界。验证旧加载不覆盖新曲结果。 |
| App 验收 | 用原创合成音频和歌词运行 macOS、iOS 模拟器：播放时高亮滚动，暂停时可点行定位，手动滚动后可恢复跟随，切曲不串词，无词或坏 sidecar 仍可播放。本轮不将模拟器结果当成 iPhone 真机验收。 |
| Web 与脚本测试 | 用本地 fixture 验证同名歌手、分页与去重、版本冲突、纯文本、无结果、限流与重试、停止采集、命名冲突、ZIP／manifest。模拟响应测试不依赖网络。 |
| 联调 | 用同一份合成两轨曲库从 Web 导出，再放到 Tinytune 授权目录，验证实际播放与时码同步。另做少量上游 API 冒烟请求，分别记录通与不通；不以冒烟请求推断覆盖率。 |
