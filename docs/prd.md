# Tinytune PRD：轻量本地音乐播放器

> 版本：v1.0 规划稿 · 2026-11-19 · 界面规格：[UI Design](ui-design.md) · 交付顺序：[Roadmap](roadmap.md)

## 1. 产品定位与发布范围

**导入一个文件夹，按歌手和专辑找到音乐，随时继续听。** Tinytune 面向在电脑上自行整理音乐文件的单用户，首发覆盖 iPhone（iOS 17+）与原生 Mac（macOS 14+）。两端独立建库，不共享数据；播放和整理规则一致，操作遵循各端习惯。目标库规模为数百到 5,000 首，支持简体中文和英文界面，音乐标签不翻译。

- **典型场景**：导入按歌手／专辑分层的目录；从专辑顺序播放；凭歌名或歌手找歌；在 iPhone 锁屏、后台及耳机上继续控制；重启后从上次位置手动继续。
- **首发成功条件**：首次使用者无需登录或读帮助就能选目录并播出第一首；重启后授权可用时无需重选目录；目录失联能识别并恢复；任何“移除”都不改动原始音乐文件。具体门槛见 §7。
- **不做**：后端、登录、遥测、广告、流媒体、App 联网获取歌词／封面、音频或元数据跨端同步、自动下载云端占位、改写标签或整理磁盘目录。不读取 Apple Music 媒体库，不导入 DRM 内容。首发不为 iPad、watchOS、CarPlay 做专用界面。
- **本地歌词**：播放时读取音频旁同名的 UTF-8 `.lrc`，也可在唱片页预览并导入本地 `.lrc`，优先显示绑定到当前曲目的私有副本。移除副本后回退到同目录歌词；不改原文件。支持同步高亮与点句定位。线上搜索和下载不进入 App，使用独立 [Web／CLI 工作台](../tools/LyricsWorkbench/README.md)。
- **身份与分发**：产品名 `Tinytune`；Bundle ID 使用所有者实际确认的反向域名，以 `PRODUCT_BUNDLE_IDENTIFIER` 配置；开发标识不用于分发。先交付签名、自用可安装的双端版本；公开上架另行决定。

| 优先级 | 交付范围 |
| --- | --- |
| P0 · v1.0 | 文件夹只读引用、递归导入、基础解析与封面、扫描摘要、重扫与恢复授权、歌手／专辑／歌曲浏览与搜索、播放队列、系统媒体控制、本地续播、库内安全移除 |
| P1 · v1.1 候选 | 解析来源切换、预览手工修正与库内改名、Mac 拖入文件夹、队列重排及「下一首播放」 |
| P2 · 不承诺 | 自建播放列表、跨来源内容去重、Mac 菜单栏迷你控制。云同步不在当前路线图内。 |

## 2. 音乐来源、导入与恢复

### R-01 · 授权与来源身份

- 一次选择一个文件夹，可先后添加多个来源。iPhone 显示系统「文件」选取器，推荐「我的 iPhone」下已落地的音乐；Mac 使用系统打开面板，支持本机目录及已挂载的本地外接卷。首发不保证 iCloud Drive、第三方文件提供商及网络卷可用，**不主动下载**；提示先把文件放到本机再试。
- **导入＝加入索引，不复制文件。** 原目录仍是播放来源；App 仅在自身容器保存授权、索引、设置、续播记录和可重建的封面缩略图。不重命名、移动、删除源文件，不申请全盘访问。
- iOS 按系统目录选择器的授权 URL 建立并恢复书签；macOS 同样使用系统选取器，启用 App Sandbox 的用户选取只读访问及 app-scoped bookmark，创建只读书签。不可把 macOS 专用的 bookmark options 直接用于 iOS。根目录 scope 由平台适配层托管；开始／结束配对，并存扫描与播放各持独立 lease；播放 lease 覆盖媒体实际读取周期，不能在创建 `AVPlayerItem` 后立即关闭。书签可解析但已陈旧时，在能读取目录的前提下刷新；无法恢复则标为需授权或来源离线，不删索引。仅在实际打开文件时使用当前来源的有效授权；重新拼接路径时重新确认仍在根内，拒绝扫描后被替换成链接的路径。
- 每个来源有稳定 `rootID`。能验证为同一目录时引导重扫，能验证为已导入来源的父／子目录时提示改扫已有来源。用平台可取得的目录身份与解析后的路径判断，不用显示名称或书签字节作身份；无法验证的跨来源副本不做全局去重。持久化的文件身份为 `rootID + relativePath`，路径保持文件系统实际大小写和拼写。

### R-02 · 择目录 → 扫描 → 摘要 → 确认

1. 递归扫描普通文件；忽略隐藏项、包／bundle、符号链接和别名，不跟随链接、不越出已授权根。对外部文件提供商读取按平台规则做协调与取消；系统不能立即中断的 I/O 结果在取消后丢弃，不能提交。
2. MP3、M4A（AAC／ALAC）、AAC、WAV、FLAC 是**候选支持格式**。扩展名只作候选筛选；解析容器、可播放音轨与时长后才入库。拒绝受保护、坏文件或没有音轨的文件。M0 用双端样本验证 codec／容器／seek，确认的组合才列入发布说明，MP3 和 M4A（AAC）是最低上线矩阵。封面或标签单独失败不影响可播放的文件入库。
3. 扫描分阶段显示已检查数和可导入数，不虚构总数或百分比。摘要分别显示新增、更新、未变化、跳过，以及重扫可确认的缺失项；按原因展开有限条文件名示例。已识别但未下载的文件单列；不能确认的只显示“暂时无法读取”。有有效结果时允许确认加入；没有可提交的变化时显示完成或选择其他来源的入口，不生成空来源。
4. 扫描结果放在临时区；用户确认前不写入正式音乐库。一次只运行一个导入／重扫任务；扫描与预览可取消，当前播放不受影响。确认进入短暂提交态；提交前检查来源仍可访问、将写入的文件仍与预览匹配、缺失与不可播放状态仍成立；检测到变动时请用户重新扫描，不写入过期摘要。以单次提交应用歌曲变化、来源书签及聚合更新。失败保留旧库并可重试；中断重启后清理临时结果，正式库只呈现提交前或提交完成的状态。
5. 同来源同路径再次扫描是更新而非新增：保留歌曲 ID 和首次加入时间；大小／修改时间相同时可跳过昂贵解析，但这只是增量提示，不是内容去重依据。保留不同路径上的同名、同长度或同内容版本。源文件被替换而路径不变时保留 ID；播放时重读有效时长，恢复点超界则回到开头。

### R-03 · 重扫、恢复与安全移除

- 首发不后台监听目录。用户在「来源」手动重新扫描。**只有已成功枚举的目录范围内，明确不在清单或节点已变为不兼容的普通文件／目录、且不属于任何跳过／失败分支的旧路径，才可在确认重扫后标记为缺失。** 看到了路径但读不了属于不可用，不算缺失；来源整体失联时保留已知可用性，不把全库改成文件已删除。已有记录的文件若确认已损坏／不支持，预览单列，不当成缺失；确认后保留 ID、移出可播放列表，修复后重扫恢复。
- 重新授权时先让用户选择原文件夹；验证为同一目录则更新原来源。确实迁移了文件夹且目录身份无法匹配时，仅在「重新连接」流程中比对相对路径，要求至少一条原曲目匹配，先展示新目录、匹配／未匹配数及样例供用户辨认，再由用户确认；零匹配、无法验证任何曲目或与已有来源可确认重叠时不覆盖旧书签，可独立添加新目录或重试。重连不自动播放。
- 「从音乐库移除」支持单曲和专辑／歌手页面所列曲目的批量移除。移除时显示影响曲数，并说明原始文件不变；写入按来源和路径的排除记录，普通重扫不会自动加回。来源详情提供「恢复已移除曲目」，以恢复模式重扫，预览中列出可恢复项；确认提交时只清除这次成功恢复的排除记录并重新入库。取消／失败不清排除记录。恢复的曲目生成新 ID，不恢复旧队列。
- 「移除来源」删除该来源的书签、索引与排除记录；以后重新添加视为新来源。重扫预览单独列出确认缺失的曲目，确认后将其移出可播放列表但保留索引；不把离线、未下载、授权失效或临时读失败算进去。缺失不写排除记录，音频回到原路径且重扫成功时恢复原 ID。
- 所有移除操作会清理队列中的被移除项。若当前曲目被移除，停止播放、释放授权、清空当前项与系统 Now Playing，不自动播下一首；仍保留未受影响的待播放队列。

## 3. 整理、浏览与搜索

### R-04 · 逐字段解析与聚合

目录优先。每个直接存放音频的文件夹视为一张专辑；按来源 ID 与完整相对目录分组，不让内嵌标签拆分同一文件夹，也不合并不同位置的同名文件夹。路径末尾的 `CD 2`／`Disc 2` 等正整数碟号文件夹并入其上一级。直接放在所选文件夹下的曲目也可组成专辑，名称为所选文件夹名。

| 字段 | 取值顺序 |
| --- | --- |
| 歌名 | 从文件名提取歌名 → 仅遇到无有效名称或纯数字文件名时回退到可读的 `title` 标签 → 原文件名（不含扩展名） |
| 曲目歌手 | 文件名中可辨认的歌手 → 可读的 `artist`／`albumArtist` 标签 → 专辑上一级目录推断 →「未知歌手」 |
| 专辑归属歌手 | 可读的 `albumArtist` 标签 → 曲目歌手；归属冲突不拆专辑，也不任取一个歌手代表整张专辑。歌手页仍按演唱者显示合辑中的相应歌曲 |
| 专辑 | 实际专辑目录名，所选文件夹自身也可作为专辑目录 |
| 曲号、碟号 | 明确的文件名前导曲号／实际碟目录 → 可读的内嵌曲号／碟号 → 两至三位纯编号且有有效非数字标签歌名时用编号（如 09、10、11；四位年份不推断） → 无值 |

| 相对于所选目录的路径 | 歌手／专辑／曲名 |
| --- | --- |
| `周杰伦/叶惠美/02 晴天.mp3` | 周杰伦／叶惠美／晴天（曲号 2） |
| `Beyond/灰色轨迹-Beyond.mp3` | Beyond／Beyond／灰色轨迹，即使内嵌标题乱码 |
| `周杰伦/晴天 (Live).mp3` | 可靠标签歌手（没有则未知）／周杰伦／晴天 (Live) |
| `陈奕迅 - 浮夸.m4a` | 陈奕迅／所选文件夹名／浮夸 |
| `合辑/年度精选/Disc 2/03 歌名.flac` | 合辑／年度精选／歌名（碟号 2，曲号 3） |

- 文件名提取明确的前导曲号，清除 `[320k]` 等已知音质后缀。`歌名-歌手` 仅在尾部匹配目录或已知歌手时识别，保留不像歌手的连字符和 `(Live)` 等版本信息。内嵌标签用于必要的回退和封面，不写回音频。
- 既有曲库用已索引的相对路径在读取时显示新名称及分组，不必重扫，也不改变曲目 ID、已保存队列或库内排除记录。旧库重扫会重新读取原始标签，即使显示值未变，也可确认这次刷新。路径仍按文件系统原拼写保存；搜索与歌手名比较统一宽度、大小写及多余空白。
- 歌曲可在应用内编辑歌名、歌手并恢复自动值；编辑随曲目 ID 保存，重扫不会覆盖，不写回音频。同名专辑显示来源与相对目录；同名歌曲分别保留，列表正文只显示歌名和歌手，不附加文件名。原文件相对路径可在「编辑显示名称」中查看。
- 封面取按专辑排序第一张有效内嵌封面（曲目本身优先用自己的封面，其次专辑封面）。无封面用专辑归属键生成稳定占位，不能成功解码也不阻断导入。缩略图按需生成、可清缓存，不联网。

### R-05 · 浏览、播放入口与搜索

- 默认进入「歌手」，可切到「专辑」「歌曲」。歌手和专辑按展示名的本地化顺序排列，同名用归属歌手（若适用）和稳定 ID 消歧；歌手详情按专辑分组；专辑详情按碟号和曲号排序（缺碟号视为 1，缺曲号排在同碟有曲号之后，再按标题及稳定 ID）。「歌曲」提供标题、歌手、加入时间排序；同值用稳定次级键，避免重扫导致顺序跳动。
- 全库搜索匹配曲名、实际歌手、专辑归属歌手、专辑名；按「歌曲／歌手／专辑」展示结果，曲目只计一次。中英文子串、大小写与宽度折叠；不承诺拼音、简繁转换或模糊搜索。可用性有文字状态，历史记录不上传，首发不保存查询历史。
- 点曲目按当下视图完整可播放集合生成队列快照（不是分页剩余部分），从所点曲目开始；搜索中的曲目按当前「歌曲」结果快照生成。专辑／歌手「播放全部」以该页当前排序从首个可播放项开始；iOS 音乐库「歌曲」也提供「播放全部」，以全库歌曲当前排序建立队列，可跨专辑续播。仅改变搜索、排序或浏览位置不改队列；明确选择另一个播放范围才替换当前队列。例外：从歌手或专辑详情点播或「播放全部」后，若在播放期间（含暂停或换歌加载）打开音乐库「歌曲」，则保留当前曲、进度、播放状态和仍可访问的播放历史，将待播范围切换到打开时的歌曲列表。若已在换歌，等换歌完成后以实际播到的曲目为起点。顺序播放从当前曲的下一首继续，到末尾停止；随机播放将列表里除当前曲外的可播歌曲无放回洗牌；单曲循环继续重播当前曲，手动下一首按歌曲列表排序。接续只发生一次，不因后来重访或重新排序而重建队列，也不会加回本次队列中手动移除的待播曲目。未使用的接续资格与手动移除记录随播放快照恢复。

## 4. 播放体验

### R-06 · 传输控制和队列

- 播放状态区分 `idle / loading / playing / paused / ended / failed`；队列和暂态播放事件由单一播放服务串行归约。`AVPlayer` 的状态/进度是展示依据，拖动进度时先显示预览，松手才 seek；未知时长或不可 seek 时禁用进度操作。快速换曲后迟到的回调不能覆盖新曲。
- 上一首：当前时间大于 3 秒回到本曲开头，否则回到上一个实际播放项；不存在上一项时回到本曲开头（若本曲不可用则禁用）。手动下一首不受单曲循环限制。三种模式互斥：顺序播放、单曲循环、随机播放；通过同一个按钮按此顺序轮换。单曲循环只在自然结束时重播当前曲；顺序与随机在待播耗尽时停止。随机无放回，一轮中各可播放项最多自然播放一次。切换模式不换当前曲；退出随机后恢复源顺序，从当前项之后继续。随机下上一首按实际历史，随后下一首先沿有效历史前进。旧快照如已启用随机，保留随机待播顺序；仅启用过列表循环则恢复为顺序播放。
- 队列呈现当前曲及按**实际播放次序**排列的待播项；P0 支持点播待播项（跳过此前的待播项，不打乱其后的顺序），只允许从队列移除待播项，且不改音乐库。此处的“移除”对本次队列快照有效，跳过则不是移除。手动点播队列项即开始播放；从暂停状态按上／下一首仅载入新曲并保持暂停。歌曲列表中不可用项不替换现有队列，提供恢复入口。
- 起播失败或播放中断读时显示当前曲错误，让用户选「重试」或「下一首」；自然推进或显式使用上／下一首遇到不可用候选时可跳过并告知。每次推进最多尝试一轮候选，无可播项则停止并提示，不无限重试。顺序或随机队列自然结束时保留最后一首和结束状态；按播放从末曲开头重播。当前项已被移除时，按播放从保留队列选择第一个可播放项。

### R-07 · 迷你播放器、续播与系统集成

- 有当前项或剩余队列时显示全局播放控制；无播放上下文时不占用音乐库空间。iPhone 提供全屏播放页、系统音量（侧边键／控制中心）；Mac 提供底部控制条、窗口内展开的播放页和 App 音量滑块。音量不改系统音量，Mac 初始值为 100%，保存用户调整。
- 本地保存队列、当前项、已播放历史／随机序列、进度和模式。在切曲、暂停、进入后台等时机及播放中至多每 5 秒做一次周期检查点；不因每次进度刷新写数据库。启动读取有效快照并恢复为暂停（已结束的保留结束），首次明确播放才打开音频并发声。快照存在但当前文件不可用时显示可恢复状态，不静默换歌或自动发声。队列或进度数据损坏时可回到空播放器，不能阻断音乐库。设置里的默认播放模式只在没有有效快照时初始化播放器；随后换队列保持当前模式。
- iOS 用 `AVAudioSession` 的 `.playback` 类别与后台音频能力；用 `MPNowPlayingInfoCenter` 与 `MPRemoteCommandCenter` 同步歌曲、时长、进度和播放命令，验证锁屏／控制中心／耳机。Mac 验证系统 Now Playing 与媒体键；空格支持播放／暂停，但不抢搜索框和系统弹窗焦点。不可用命令按队列状态禁用。
- iOS 被电话／系统音频打断时暂停；仅系统允许恢复、打断前正在播放、路由仍安全且其间用户没有明确暂停或换歌，才自动继续。耳机断开时暂停，重连不自动播放。卸载外接卷引起当前读失败时按 R-06 提示，不把来源下所有曲目标为缺失。

## 5. 原生 Swift Monorepo

**一个 Git 仓库，一个 Xcode 工程，两个原生 app targets，一个本地 Swift Package。** SwiftUI 为主，UIKit／AppKit 只补系统选取器、菜单、焦点或系统集成所需的能力；不使用 Catalyst、WebView UI、跨端运行时或第三方播放器 SDK。Swift 6 语言模式为目标，M0 固定可重复的 Xcode 版本及 CI 镜像；构建工具链不等于最低系统版本。

```text
tinytune.xcworkspace/
apps/
  Tinytune.xcodeproj/               # Tinytune-iOS / Tinytune-macOS schemes（共享）
  iOS/                            # 组合根、导航、选取器、音频会话、签名配置
  macOS/                          # 组合根、窗口、菜单、Sandbox、签名配置
  UITests/                        # 各端 XCTest / XCUITest targets
packages/TinytuneKit/
  Package.swift
  Sources/{Domain,Library,Playback,DesignSystem}/
  Tests/                          # 对应逻辑和集成测试
tests/Fixtures/                   # Swift 与 Web 共用的测试资料
scripts/                          # 构建、测试和 fixture 生成入口
.github/workflows/                # macOS runner 上构建两个目标并跑测试
docs/
```

| 模块 | 职责与依赖边界 |
| --- | --- |
| `Domain` | Swift 值类型、稳定 ID、队列 reducer、解析和排序规则、服务接口；不依赖 SwiftUI／SwiftData／AVFoundation |
| `Library` → `Domain` | SwiftData 持久化、越权防护、扫描、AVFoundation 标签读取、封面缓存、冲突处理；通过 app 注入的平台文件授权适配获取 scoped 目录 |
| `Playback` → `Domain` | AVPlayer 封装、播放状态与进度、Now Playing 集成与快照；由 app 注入可播放资源和 lease 接口，不直接读 SwiftData |
| `DesignSystem` → `Domain` | SwiftUI tokens、曲目行、封面、播放按钮、可重用状态视图与字符串资源；只消费值和用户操作，不持有播放器或数据库 |
| `apps` → 上述模块 | 两端组合与注入服务、生命周期、平台布局和导航；一个进程内只拥有一套库和播放器，Mac 首发使用单主窗口 |

扫描、解码/缩略图与存储查询不得占用主线程；UI 状态由 `@MainActor` 管理，SwiftData 写入由单一隔离 writer 串行提交，跨隔离边界传 ID／`Sendable` DTO，不传 `ModelContext` 或可变模型对象。没有共享运行时、后台服务或另一个包管理器。先共享规则和组件，再按证据拆更多模块。

## 6. 本地数据契约与隐私

| 实体 | 所有权／关键字段 |
| --- | --- |
| `ImportRoot` | `id`、显示名、bookmark、可选平台目录标识、最后成功扫描时间、来源状态（可用／需授权／离线／暂不可读） |
| `Track`（旧稿 `Song`） | `id`、`rootID`、`relativePath`、派生唯一 `sourceKey`；标签原值、展示字段／搜索键、文件大小／mtime、时长、碟号／曲号、`dateAdded`、可用性、缩略图引用；是唯一持有文件相对路径用于播放的模型 |
| `Artist`、`Album` | 聚合键、显示名、稳定 ID、封面键；Album 对应归属歌手，Track 同时保留实际歌手；空聚合在无引用后清理，不级联删除其他来源曲目 |
| `ExcludedPath` | `rootID` + 相对路径的排除键；用于显式库内移除后的重扫过滤，不视为音频文件引用 |
| `PlaybackSnapshot` | 版本、队列及有效播放顺序／历史、当前 ID、时间戳／位置、模式；与音乐库索引解耦，可原子写入单独文件 |
| `Preferences` | 本地简单偏好（默认播放模式、Mac App 音量等），不保存书签、文件路径或搜索历史 |

- 最低系统不依赖后续 SwiftData 的 `#Unique`／`#Index` 宏。复合键用单字段无歧义编码与 `@Attribute(.unique)` 表达；显式按键查找并更新原记录，不用碰撞隐式 upsert 覆盖稳定 ID。通过批量查询、列表分页与基准测试验证性能；仅性能证据表明需要时再引入持久化优化。
- SwiftData 从首版定义 `VersionedSchema`／迁移计划，明确 `cloudKitDatabase: .none`。迁移或存储打开失败保留旧 store，显示「重试」和可读错误，不静默删除或重建。音频不进数据库；缩略图在 Caches，删除缓存不影响索引与音频。
- 无账号、无第三方 SDK、无 App 主动网络请求。仅保留本地系统日志，默认不输出绝对路径、文件名、书签和标签；诊断仅记录枚举原因、数量、耗时。源文件不受 App 卸载影响，不承诺 App 本地索引备份、书签迁移或跨设备恢复。是否公开分发及隐私声明检查在发布阶段按实际产物决定。

## 7. P0 验收与质量门槛

以下是**目标，不是实测结果**；M0 固定 fixture、目标设备、签名与测量方法，M4 附测试结果。可用合成音频复用媒体体积，但格式与故障验证必须使用真正对应的 fixture。

| ID | 验收标准 |
| --- | --- |
| AC-01 | 两端首次进入 → 选择本机目录 → 确认摘要 → 按歌手或搜索播出；首次使用观察中至少 4/5 人无需指导，在 2 分钟内完成 30 首样本的流程（含扫描）。只做本地观察，不内嵌埋点。 |
| AC-02 | 冷重启后可读取既有来源；撤销访问、拔盘或移动目录能区分故障并恢复，重连后索引不重复，原路径匹配的曲目保持 ID；原始文件内容及目录树未变。 |
| AC-03 | 取消扫描或退出预览无正式库修改；提交失败不留半成品；混合标签、大小写、坏文件、无封面、循环链接和部分子树读取失败均有 fixture。重扫不因授权失败而误报缺失，库内移除不会被普通重扫撤销。 |
| AC-04 | 播放／暂停、seek、上／下一首、顺序／单曲循环／随机切换、队列跳播／移除和失败耗尽用确定性测试覆盖。冷启动保持静音，在有暂停快照时明确点击才恢复，正常退出的恢复点误差目标 ≤5 秒。 |
| AC-05 | 真机验证 iPhone 锁屏、后台切曲、控制中心、耳机断开和来电；Mac 验证媒体键、系统 Now Playing、外接卷移除和空格的焦点行为。最低系统与一个较新系统版本均需纳入回归。 |
| AC-06 | 短音频基准：1,000 首本地样本到摘要 ≤45 s（3 次冷扫描取中位数）；5,000 首库冷启动到可浏览 ≤2.5 s；搜索输入到结果可交互 ≤350 ms（包括去抖，30 次取 P95）；本机 MP3／M4A（AAC）点播到出声 ≤1 s（20 次取 P95）。后 3 项使用 Release 构建，在锁定的 iPhone 与 Mac 上分别记录；扫描时列表与既有播放仍可用。 |
| AC-07 | 两端断网完成导入、搜索、播放和重启续播；迁移回归和异常存储测试不会删除旧库；简中／英文、浅／深色、辅助功能与空态完整，按 [UI QA](ui-design.md#9-设计验收) 核对。 |
