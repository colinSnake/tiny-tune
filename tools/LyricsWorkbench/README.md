# Tinytune 音乐工作台

本地 Web 工具：按歌名或歌手搜索，选择同一版录音试听并查看歌词，将完整音频与同名歌词一起下载。原有本地歌词工具、命令行采集及批量 LRC 导出保留。使用 Vite、React、TypeScript、Node.js 和 Fastify。

## 启动网页

需要 Node.js 22.18 或以上，以及 `package.json` 指定的 pnpm 版本。从仓库根目录运行：

```sh
cd tools/LyricsWorkbench
pnpm install --frozen-lockfile
pnpm dev
```

访问 `http://127.0.0.1:9117`。开发模式只启动一个 Fastify 服务：页面、API 和 Vite 热更新共用同一端口，不需要另起 Vite 或配置 API 代理。修改 `.env.local` 后需重启开发服务。服务只监听本机；不要把本实例直接暴露到公网。默认作者曲库不需要 API Key，需要联网试听和下载。

构建并以生产模式本机预览：

```sh
pnpm build
pnpm start
```

构建生成 `dist/public/`（静态页面和资源）与 `dist/server/index.js`（服务端入口）。生产模式由 Fastify 提供静态资源和 API，不启动 Vite，默认访问 `http://127.0.0.1:9120`。开发和生产都可以用 `PORT` 环境变量更换端口，例如 `PORT=8080 pnpm dev`。

## 下载整曲＋歌词

1. 输入歌名或歌手，按 **Enter** 或点「搜索歌曲」。可用来源并行查询，先返回的结果可以立即操作；某来源失败时可以单独重试。推荐用「歌名 + 歌手」缩小范围。
2. 搜索全部成功且录音足够明确时，页面自动展开详情；有多个版本时请按专辑、时长和来源选择。支持试听的录音可查看配套歌词；「仅歌词」可以预览原文和来源时码，但不播放音频、不生成整曲 ZIP，也不会拿来自动绑定另一个来源的录音。
3. 点结果行的「下载」，不必先打开详情或导入文件。解压后保持 MP3 与 `.lrc` 同名同目录；`manifest.json` 记录录音、歌词来源、署名和许可。服务端按录音 ID 重查，验证完整 MP3 后才发送 ZIP，不重编码。

- **作者曲库：** 默认收录 Jonathan Coulton 的 [Code Monkey 原版录音](https://www.jonathancoulton.com/2006/04/14/thing-a-week-29-code-monkey/)；[作者说明](https://www.jonathancoulton.com/faq/)授予非商业使用及分享权限，需保留署名和来源。歌词使用该录音的 [JoCopedia 对应版本](https://joco.wiki.gg/wiki/Code_Monkey/Lyrics?oldid=5403)。程序不内置音频或歌词副本，从确认过的地址获取，并校验两份内容的摘要；源文件变化时不会静默改下其他版本。
- **Jamendo：** 在 `.env.local` 填写自己的 `JAMENDO_CLIENT_ID` 后可扩展搜索和试听。Jamendo [API 条款](https://devportal.jamendo.com/api_terms_of_use)限制以离线访问为目的的应用；曲目有下载标志不代表应用可打包歌词。只有在取得平台对这一用途的许可、逐首核对音频和歌词使用许可后，才设 `JAMENDO_BUNDLE_AUTHORIZED=1` 并将审阅过的整曲 MP3 摘要写入 `JAMENDO_APPROVED_MP3_SHA256`（`曲目ID:64位小写SHA256`，多首逗号分隔；使用 Jamendo `mp32` 下载文件的摘要）。服务端仍检查来源返回的下载标志、许可与同一录音 ID 上的歌词。B 站与其他商业曲库尚未接入，不会用翻唱或试听片段替代整曲。
- **LRCLIB：** 默认开启，补充歌名、歌手与歌词搜索。2026 年 11 月 23 日用 10 首华语歌曲与 3 首作者曲抽测，13 首均找到歌词候选；同曲名、同歌手也可能有不同专辑或录音，候选不代表歌词可与当前音源绑定或可打包分发。同期试查 Audius，13 首均未找到歌名与歌手都精确匹配的结果，未接入。当前默认整曲下载仍限已核对的作者曲目，没有华语完整音频目录；可点「试搜 Code Monkey」验证下载流程。

## 给已有歌曲找歌词

点击页首「给本地音乐补歌词」，在同一页面展开工具。这一步只用于已有音频，不是整曲下载的前置步骤。可点击「试用合成样例」离线检查逐句定位与歌词导出。

1. 输入歌手名称或别名，按 **Enter** 或点「搜索歌手」。唯一精确命中直接展开；有多个候选时，请按地区和说明选定歌手。每页最多加载 50 条录音。
2. 点击曲名即可查这首的歌词，不必先勾选。勾选用于批量匹配和导出；批量仍遵守上游限流，可停止剩余请求、重试失败项。只有录音版本足够明确才自动确认歌词，有歧义时可预览并确认候选。
3. 打开「导入本地音频」，拖入文件夹（含子文件夹），或用「选择音频文件」多选；核对数量后点「确认导入」。手动选文件会打开系统文件选择器，拖入目录不走浏览器的上传确认。工作台读取文件标签和时长，版本明确才自动配对；只有文件名或碰到同名版本时，请从「本地候选」确认，或为单曲选择文件。单文件上限 200 MiB。音频不上传、不改写原件。
4. 「更多音源」支持你有权播放的 HTTPS 音频直链（本机服务可用 HTTP），不是歌曲网页。浏览器直接请求该音源，不经过工作台服务器。整曲时长与歌词版本相符才启用逐句跟随及点击定位；片段、时长冲突或不可定位的流不会强行跳转。没有可播放音源时仍可查词和导出。
5. 音源与已确认歌词按录音 ID 保存在此浏览器，切歌或刷新后重新打开同一录音即可恢复。导入会占用网站本地存储；可通过「清空曲库」确认移除副本，原文件不会被删除。清理浏览器站点数据会移除曲库和绑定，`9117` 与 `9120` 的存储互相独立。
6. 下载单曲 `.lrc`，或用 ZIP 导出已确认歌词和 `manifest.json`。曲目列表可用时也可以单独导出清单。导出不包含音频；纯文本不会生成假的时码。

Web 端业务确认复用 `WorkbenchDialog`，不使用 `window.alert()`、`window.confirm()` 或 `window.prompt()`。文件选择器和系统权限提示仍由浏览器或操作系统控制。

## 命令行采集

```sh
pnpm collect '歌手名称' --limit 50 --out ./export
pnpm collect --artist-id '你的 MusicBrainz 歌手 ID' --limit 100 --out ./export
```

只在歌手名称或别名精确对应到唯一候选时自动使用；否则打印候选 ID，使用 `--artist-id` 再试。`--limit` 可设为 1–500，默认 50。脚本输出自动确认的歌词及清单；歧义只记录状态，需到 Web 端人工确认。不会覆盖已有文件。`Ctrl+C` 保留已完成的结果。

## 放回 Tinytune

例如，把 `01 晴天.lrc` 放到 `01 晴天.flac` 同目录。**文件主名（包括曲序、空格和版本后缀）必须一致**，扩展名用 `.lrc`。单曲导出绑定本地音频时使用该音频主名；批量 ZIP 默认用曲名，对照清单处理重名和不同版本。歌词保存后无需重新扫描：打开或关闭后重开歌词视图即可重新读取。

- macOS：点播放器底栏的引号气泡「歌词」，打开右侧歌词栏。
- iOS：打开「正在播放」，点引号气泡「歌词」。点击时码行可跳转，手动滚动后可点「回到当前句」。
- App 支持 UTF-8（含 BOM）的逐行 LRC、含偏移和多时码的常见格式，以及无时码的纯文本。不改写音频或标签。

用独立测试曲库验证 iPhone 时，见[时码歌词体验验收步骤](../../docs/native-development-validation.md#iphone-时码歌词验收)。

## 来源、限制与验证

本地歌词工具和命令行采集的曲目使用 [MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API)，选中匹配时查询录音对应的发行信息；歌词使用 [LRCLIB v1](https://lrclib.net/docs.txt) 的搜索接口。这两项功能的查询只发给对应的固定来源，并遵守限速。歌手搜索的成功响应在同一服务进程内缓存两分钟；遇到繁忙或限流，页面会显示重试倒计时。公开查询不等于可再分发，请只保存你有权使用的歌词。录音、专辑和歌词以数据源收录为准；不保证覆盖歌手全集。若已注册 LRCLIB，可在 `.env.local` 提供服务端 `LRCLIB_API_KEY`，不要加 `VITE_` 前缀，以免暴露到前端。
