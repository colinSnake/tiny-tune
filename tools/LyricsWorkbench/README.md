# 听页歌曲与歌词工作台 · Tinytune

本地 Web 工具（产品品牌「听页」）：一次搜索，左侧查看本地与在线歌曲，右侧试听和查看歌词，直接保存到配置曲库或导出。无独立歌词页面、版本确认弹窗或必须勾选的中间步骤；批量操作按需使用。使用 Vite、React、TypeScript、Node.js 和 Fastify。

## 启动网页

需要 Node.js 22.18 或以上，以及 `package.json` 指定的 pnpm 版本。从仓库根目录运行：

```sh
cd tools/LyricsWorkbench
pnpm install --frozen-lockfile
pnpm dev
```

访问 `http://127.0.0.1:9117`。开发模式只启动一个 Fastify 服务：页面、API 和 Vite 热更新共用同一端口，不需要另起 Vite 或配置 API 代理。修改 `.env.local` 后需重启开发服务。服务只监听本机；不要把本实例直接暴露到公网。默认作者曲库不需要 API Key，需要联网试听和下载。

品牌标志采用折页音符「听页」Logo，页面以鸢尾紫到玫瑰粉为品牌渐变；按钮和提示保留可读的实色语义。网页标题、字标和歌名使用本机个人测试用的「上首软糖体」；歌词正文、歌手和操作控件使用系统字体。项目不会打包或提交这款字体。若需启用，请将你获准个人使用的字体文件放在仓库根目录 `.local/fonts/ruantang.ttf`。缺少本机字体时也会回退至系统字体。`.local/` 已由仓库忽略。

构建并以生产模式本机预览：

```sh
pnpm build
pnpm start
```

构建生成 `dist/public/`（静态页面和资源）与 `dist/server/index.js`（服务端入口）。生产模式由 Fastify 提供静态资源和 API，不启动 Vite，默认访问 `http://127.0.0.1:9120`。开发和生产都可以用 `PORT` 环境变量更换端口，例如 `PORT=8080 pnpm dev`。

## 歌曲与歌词统一工作区

- 页面固定在当前视口，桌面左右面板等高；仅歌曲列表显示 4px 宽／高的内部滚动条。窄屏上下排列，歌词与详情仍可内部滚动，但不显示滚动条。
- 输入歌手或歌名，按 Enter 或点「搜索」。本地曲库、歌手录音目录和在线来源并行加载，已返回的结果可直接操作。
- 歌曲行默认两行：第一行歌名，第二行歌手与「已下载／未下载」；时长和试听／暂停、下载图标固定靠右。长歌名省略，悬停可看全名。图标默认没有底色，仅悬停或键盘聚焦时出现背景。
- 搜索后自动查找当前选中歌曲的歌词，切换歌曲时自动更新，不对所有结果发起批量查词。版本与重查操作放在独立歌词区，来源播放器按需展开。B 站分集会提取歌名及明确的歌手署名。视频歌词未核对到同一音源时码时，只保存无时码的同名纯文本 `.lrc`，不伪装成同步歌词；若存在不同正文候选，须先在右侧选择歌词版本。保存结果分别提示歌词缺失、版本待选、来源异常和封面失败；新保存或已存在的纯文本都会提示无时码。暂无音频的来源会禁用试听和音频下载。
- 顶部统一提供「一键下载」「保存到本机目录」：未勾选时操作当前歌曲，勾选后操作所选歌曲，每次最多 50 首。单行下载图标只下载该行歌曲，不受其他勾选影响。
- 本地录音保存歌词到原音频同目录、同主名的 `.lrc`，不重命名或修改音频；只有存在符合版本及音频时长的时码时，才保存为可自动滚动的配套歌词。已有纯文本或同步歌词直接读取，不依赖网络。要升级纯文本，在右侧点「查找歌词时码」，明确选择同版候选，再点「补齐歌词时码」；在线查询失败、正文不一致或文件已变化时保留原文。
- 开放下载的在线音频按歌手归档，有可核对的发行信息时再设专辑子目录；视频合集不当作专辑。配套歌词与音频同名保存；没有配套音频的歌词保存到「歌手／独立歌词」。旧路径的已有录音不会重复下载入库或挪动；可核验为相同录音才补写配套时码歌词。视频录音可先保存音频，再在本地录音行核对同步歌词版本；不自动套用其他录音的时码。批量结果分别显示新保存、补词、已存在和未处理。

「已下载」表示本地已有音频，或本次会话的音频下载／本地保存已成功；不表示仅有歌词或来源允许下载。浏览器导出无法确认用户之后移动或删除的文件，刷新后以曲库扫描为准。

「导出 .lrc」不要求先确认或导入音频。混合 ZIP 保留本地原始目录、在线发行归档、配套歌词和来源清单。源站只提供试听或歌词的项目，不会伪装成可下载音频。下载后的音频可直接在右侧试听，缓存最多 160 MiB，刷新会清空。

**导入 Tinytune：** 先解压，再选择包含所有歌手目录的解压根目录作为音乐来源，不要逐首导入。扫描只把音频入库；即使扫描摘要把 `.lrc` 和 `manifest.json` 列为跳过的非音频文件，播放时仍会读取同名歌词。若要合并多个包，把确认属于同一发行的音频与歌词放在同一个实际专辑目录，保留各包的来源清单，遇到同名文件先核对、不要覆盖。本机验收时 macOS 的 `/usr/bin/unzip` 没有正确处理中文路径；命令行可用 `ditto -x -k 下载包.zip 解压目录`。

- **作者曲库：** 默认收录 Jonathan Coulton 的 [Code Monkey 原版录音](https://www.jonathancoulton.com/2006/04/14/thing-a-week-29-code-monkey/)；[作者说明](https://www.jonathancoulton.com/faq/)授予非商业使用及分享权限，需保留署名和来源。歌词使用该录音的 [JoCopedia 对应版本](https://joco.wiki.gg/wiki/Code_Monkey/Lyrics?oldid=5403)。另收录 [Creative Commons Taiwan《歡迎來唱我的歌》](https://web-archive-2025.creativecommons.tw/downloads/488.html) 发布的 5 个有词录音（包括《天公伯仔》原版和 Remix），按 [CC BY-NC-SA 2.0 TW](https://creativecommons.org/licenses/by-nc-sa/2.0/tw/) 使用。可搜「朱約信」「猪头皮」或曲名的简繁写法；源歌词是纯文本，保留署名，不生成时码；如需原字形，下载前可选择「保留原文」。程序仅存曲目元数据和摘要，不内置音频或歌词副本；ZIP 重新验证完整文件后才下载。
- **Jamendo：** 在 `.env.local` 填写自己的 `JAMENDO_CLIENT_ID` 后可扩展搜索和试听。Jamendo [API 条款](https://devportal.jamendo.com/api_terms_of_use)限制以离线访问为目的的应用；曲目有下载标志不代表应用可打包歌词。只有在取得平台对这一用途的许可、逐首核对音频和歌词使用许可后，才设 `JAMENDO_BUNDLE_AUTHORIZED=1` 并将审阅过的整曲 MP3 摘要写入 `JAMENDO_APPROVED_MP3_SHA256`（`曲目ID:64位小写SHA256`，多首逗号分隔；使用 Jamendo `mp32` 下载文件的摘要）。服务端仍检查来源返回的下载标志、许可与同一录音 ID 上的歌词。商业曲库尚未接入，不会用翻唱或试听片段替代整曲。
- **LRCLIB：** 默认开启，补充歌名、歌手与歌词搜索。2026 年 11 月 23 日用 10 首华语歌曲与 3 首作者曲抽测，13 首均找到歌词候选；同曲名、同歌手也可能有不同专辑或录音，候选不代表歌词可与当前音源绑定或可打包分发。同期试查 Audius，13 首均未找到歌名与歌手都精确匹配的结果，未接入。整曲下载仅限已核对的音轨和歌词，不含华语商业曲库；可点「试搜 朱約信」或「试搜 Code Monkey」验证下载流程。

## B 站搜索与下载

- **B 站搜索：** 在同一个搜索框输入「李克勤」或「李克勤 红日」，按 Enter。列表展示单曲投稿和部分合集分集，保留投稿者和分集号；点结果可加载对应 B 站播放器，或打开原投稿。只读取首页的音乐类结果，优先展开标有曲名或分集的合集；未展开的其他分集可在原站查看。来源不可用或限流时，可单独重试或直接在 B 站打开同一搜索。搜索不需要安装下载工具，也不使用账号或 Cookie。
- **仅 MP3：** 支持把符合下载条件的公开投稿分集保存为 MP3，不用填写 BV 号、摘要或导入音频。已检查的分集可从列表直接下载；显示「查看详情」的投稿，点开后再检查。Fastify 会重新核对所选分集，只处理无需登录、没有付费或充电限制、上游有下载标记且投稿未明确禁止下载的 15 分钟以内片段。转码后校验整段时长，不附其他版本歌词。功能仅供本机使用；公开播放与站内下载标记不代表可转载，请只保存你有权使用的内容。
- **B 站授权曲库（ZIP）：** 只给已核对授权、完整音轨及同版本歌词的录音开放 ZIP。可下载样本是 [《自由软件之歌》OpenUTAU 4/4 演绎版](https://www.bilibili.com/video/BV1QE421w7GX/)，由投稿者按 CC BY-SA 4.0 授权。搜索「自由软件之歌」或「Diamochang」，从列表直接下载，或打开详情加载 B 站播放器。歌词从[投稿者同一版本的演唱工程](https://github.com/Diamochang/free-software-song-openutau/tree/3845741485b10cb70c36f13cf7c2f429f312a217)整理，使用纯文本，不从字幕推测歌词或伪造时码。

下载需要 `yt-dlp` 和带 `libmp3lame` 的 `ffmpeg`；macOS 可用 `brew install yt-dlp ffmpeg`。确保 Fastify 能找到工具后重启 `pnpm dev` 或 `pnpm start`。授权 ZIP 仍校验原音轨摘要和同版本歌词；普通 MP3 可选用 `BILIBILI_APPROVED_AUDIO_SHA256` 锁定某个分集的 CID 和原音轨（详细格式见 `.env.example`），不配置也能下载符合条件的分集。

## 本地曲库与安全保存

在线 B 站下载使用投稿明确署名和分集名生成 `歌手/歌名.mp3` 和同名的 `歌手/歌名.lrc`（有匹配歌词时），文件名不附歌手或合唱署名，无法可靠识别歌手时提示选择其他来源，不再新建“未知歌手”目录。新下载的 MP3 内嵌歌名、歌手、来源标识和可获取的投稿封面（不是保证匹配的官方专辑封面）；封面缺失不阻断音频保存。重复保存先按 B 站分集 ID 查找，使用既有文件的实际路径；有多个同来源副本则报告冲突。没有匹配来源时，同名同长只作为线索，必须比较 MP3 音频数据（允许 ID3 标签不同），不能把不同录音误报为已下载。已有音频和封面不会被重写；补写缺失歌词也需要确认音频数据一致。


在 `tools/LyricsWorkbench/.env.local` 设置本机目录，重启服务后，统一搜索会自动纳入该目录的真实文件：

```env
TINYTUNE_AUDIO_LIBRARY=/你的音乐根目录
```

目录配置只在服务端使用，不要求浏览器选目录或上传文件。已有音频沿用真实子目录与原主名，标签仅用于检索和录音核对，不据此重建目录；可逆的 UTF-8／Latin-1 标签误解码只修正展示，不改写文件。切换歌手会清理旧列表和选择，并忽略已过期的响应。

本地保存仅允许本机同源页面；浏览器不能提交任意路径、音频链接或歌词正文。歌词候选必须来自近期服务端查询，原时码仍需符合录音时长。纯文本可阅读或导出；在线录音保存时可写同名纯文本 `.lrc`，但不作为同步配套文件。不缩放、不挪动或生成猜测时码。新文件使用临时文件与不覆盖发布；仅单首明确补时码且正文一致、音频与歌词未变化时，才替换已核对的纯文本。重复同名文件、同主名多格式音频与符号链接不会被覆盖。

操作栏的「歌词」默认选「简体中文」，可切换为「保留原文」。即时应用到右侧歌词预览，也用于保存、单首或批量下载及独立歌词导出；不改变 LRC 时码、元数据标签、文件名或音频。已有歌词不会因切换字形而覆盖。

没有配置曲库时仍可搜索、试听可用来源和导出，不显示不可用的直接保存操作。原来的独立补词折叠区、手动导入音源向导和样例入口不再挂载到新工作区；命令行采集保持独立可用。

## 命令行采集

```sh
pnpm collect '歌手名称' --limit 50 --out ./export
pnpm collect --artist-id '你的 MusicBrainz 歌手 ID' --limit 100 --out ./export
```

只在歌手名称或别名精确对应到唯一候选时自动使用；否则打印候选 ID，使用 `--artist-id` 再试。`--limit` 可设为 1–500，默认 50。脚本输出自动确认的歌词及清单；歧义只记录状态，可到 Web 端选择合适版本后导出。不会覆盖已有文件。`Ctrl+C` 保留已完成的结果。

## 放回 Tinytune

单曲推荐直接导入：下载已核对版本的 UTF-8 `.lrc`，在 Tinytune 唱片页选择「导入歌词…」（已有歌词时在歌词区的「…」菜单中）。预览并对照音频相对路径确认后导入，不必把 `.lrc` 重命名或放到原音频目录。

也可以把 `01 晴天.lrc` 放到 `01 晴天.flac` 同目录。**文件主名（包括曲序、空格和版本后缀）必须一致**，扩展名用 `.lrc`。单曲导出绑定本地音频时使用该音频主名；Web 批量 ZIP 中的本地录音也沿用原相对目录与主文件名；在线歌词按歌手／专辑分组，对照清单处理不同版本。歌词保存后无需重新扫描：歌词区如果显示没有歌词或读取失败，点「重新读取歌词」即可。

- macOS：在「正在播放」唱片页查看，或从播放器底栏打开右侧歌词栏。
- iOS：在「正在播放」唱片页查看歌词。展开后可点时码行跳转，手动滚动后可点「回到当前句」。
- App 支持 UTF-8（含 BOM）的逐行 LRC、含偏移和多时码的常见格式，以及无时码的纯文本。不改写音频或标签。

用独立测试曲库验证 iPhone 时，见[时码歌词体验验收步骤](../../docs/native-development-validation.md#iphone-时码歌词验收)。

## 来源、限制与验证

本地歌词工具和命令行采集的曲目使用 [MusicBrainz](https://musicbrainz.org/doc/MusicBrainz_API)，选中匹配时查询录音对应的发行信息；歌词使用 [LRCLIB v1](https://lrclib.net/docs.txt) 的搜索接口。这两项功能的查询只发给对应的固定来源，并遵守限速。歌手搜索的成功响应在同一服务进程内缓存两分钟；遇到在线来源繁忙或限流，页面会显示重试倒计时。公开查询不等于可再分发，请只保存你有权使用的歌词。录音、专辑和歌词以数据源收录为准；不保证覆盖歌手全集。若已注册 LRCLIB，可在 `.env.local` 提供服务端 `LRCLIB_API_KEY`，不要加 `VITE_` 前缀，以免暴露到前端。

```sh
pnpm test
pnpm typecheck
pnpm build
```


## 歌词质量与音源质量边界

- 歌词候选的同步/纯文本字段作为整条记录校验：拼音注音、跨字段注音、HTML、损坏字符、NUL/异常控制字符、坏时码与超出录音长度的时轴均不能借纯文本降级绕过校验。合法双语、衬词、偏移和多时间标签保留。
- 本地保存和 ZIP 导出会重新验证，不信任旧的 ready 状态。本地保存遇到坏歌词时仍可保存已验证音频，但不写坏的 sidecar，并报告 `lyricsIssue: unsynced`；ZIP 需要有效歌词，验证失败时不下载音频。既有坏歌词标为 protected，不自动覆写。
- B 站 MP3 输出改为 `libmp3lame -q:a 0` 高质量 VBR，不再统一固定 128 kbps；仍按原音轨摘要、实际 MP3 帧和时长验证。此设置只减少额外转码损失，不能恢复源文件缺失的细节，也不代表无损或录音棚版。已有本地音频不自动转码或替换。

### 后续音源优化建议（尚未接入）

当前已有作者曲库、授权 B 站、普通 B 站发现和可配置的 Jamendo 适配器；LRCLIB 只提供歌词，不是音频源。新增商业曲库不能只替换一个搜索地址，应单独核实完整音频下载授权、可用性和同版本识别。

1. 优先导入用户已合法获取的录音棚原文件或接入允许完整下载的授权源，避免把视频转码当母带来源；后续保留原始 M4A/FLAC，MP3 仅作为兼容导出。
2. 引入 studio/live/cover/remix/unknown 版本标记。默认录音棚优先，现场/翻唱单独可选，未知来源明确标注，不能凭标题“无损/原版”认定版本。**当前搜索尚未实现这项分类与过滤。**
3. 区分源编码、源码率、采样率与导出编码；未知则显示未知，不以转码后的码率伪装源音质。
4. 先确认录音版本，再用歌手、歌名、发行信息与实际时长匹配歌词。找不到同版时保留缺失状态，不把现场音频与录音棚歌词强行配对。
5. B 站作为补充入口而非高音质保证；主流商业录音的完整曲库接入另走官方授权或用户自有文件，不使用绕过付费/DRM 的下载接口。
